# Weixin iLink transport

`weixin-api.mjs` is Mirally's independently written HTTP client for the public iLink wire protocol. It imports no OpenClaw package and has no Agent loop, account persistence, retry queue or conversation state. The product channel owner supplies credentials, message IDs, context tokens, route decisions and cancellation; it owns all persistence and retries.

The reviewed protocol baseline is Tencent `openclaw-weixin` **2.4.10**, commit [`874637a0dbc24050f72d1385add4fc6170a2d726`](https://github.com/Tencent/openclaw-weixin/tree/874637a0dbc24050f72d1385add4fc6170a2d726): [protocol](https://github.com/Tencent/openclaw-weixin/blob/874637a0dbc24050f72d1385add4fc6170a2d726/docs/protocol_zh_CN.md), [HTTP API implementation](https://github.com/Tencent/openclaw-weixin/blob/874637a0dbc24050f72d1385add4fc6170a2d726/src/api/api.ts), [QR lifecycle](https://github.com/Tencent/openclaw-weixin/blob/874637a0dbc24050f72d1385add4fc6170a2d726/src/auth/login-qr.ts), [wire types](https://github.com/Tencent/openclaw-weixin/blob/874637a0dbc24050f72d1385add4fc6170a2d726/src/api/types.ts), and [MIT license, copyright Tencent 2026](https://github.com/Tencent/openclaw-weixin/blob/874637a0dbc24050f72d1385add4fc6170a2d726/LICENSE). No source implementation or OpenClaw SDK code was copied. The default version metadata states this compatibility baseline; `bot_agent` identifies Mirally separately. The documented client behavior is not a complete server guarantee.

`WeixinApi` exposes `getQr({tokens,signal})`, `pollQr({qrcode,verifyCode,baseUrl,signal})`, `updates({token,cursor,signal})`, and `sendText({token,to,text,contextToken,clientId,signal})`. Responses retain the documented snake_case field names. Numeric message identifiers are read losslessly as strings. `validateWeixinBaseUrl(value,{allowLoopback})` returns a validated origin; production traffic is limited to HTTPS `weixin.qq.com` and its subdomains without credentials, nonstandard ports, query or path. The explicit loopback fixture option accepts only literal HTTP `127.0.0.1` or `localhost`; HTTP redirects are never followed. QR payloads are returned as inert strings for local QR encoding, never fetched or executed as markup.

Requests have a 15 second timeout (QR/update polls 35 seconds), cancellation, and a 1 MiB response bound covering the full body. The constructor accepts `requestTimeoutMs` and `pollTimeoutMs` within 1–120,000 ms. `WeixinApiError` includes `kind`, `code`, `credentialStale` for code `-14`, and, for sends, `deliveryState`. Business rejections are `rejected`; transport interruption, HTTP failure or an unusable reply are `unknown`. Never automatically retry an `unknown` send: the server may already have delivered it. Errors omit response bodies, credentials, QR query values and underlying fetch causes. The client writes no logs.

Known limits: paired private messages only; inbound voice, images, files and video are bounded and converted to the product's speech/material interfaces. Explicitly requested conversation-owned artifacts may be sent as files, images or video through the durable outbox. Typing and lifecycle signals are best effort; neither proves user presence. Protocol definitions are not proof of any account's live entitlement. Login/pairing confirmation, cursor commit, inbound deduplication and unknown-delivery handling belong to the channel service. Protocol verification uses local HTTP and injected fetch; it neither signs in nor sends a real message.

The channel sends a short receipt after an ordinary text input is admitted to the shared model session, without awaiting the completed turn. The receipt names the mode that accepted it (assistant or direct conversation). A separate `received:<command_id>` outbox identity cannot suppress or replace the final reply. Only receipts belonging to live turns in this channel process may be sent: completion or restart suppresses an unsent processing notice. Failed or unknown receipt delivery never replays the input. This is text feedback, not the protocol's typing indicator. Explicit Chinese session commands and exact title matching compose the existing route owner; they do not introduce a routing model or a second transcript.

Every user-visible prompt is defined in the exported `WEIXIN_TEXT` table in `weixin.mjs` (and `LIST_TEXT` for numbered lists); channel tests import those constants instead of repeating literals. A submitted turn whose result is unknown is never described as something to resend, and `/stop` reports a stop only when a turn was actually running.

The assistant locates conversations and may delegate an explicit instruction to the original session. Background jobs remain owned by that session; the channel has no separate work owner.

Numbered conversation pages keep only a bounded in-memory snapshot of their displayed stable IDs. A snapshot activates only after every part of that list has a successful send receipt, and is fenced to the original installation, route revision and conversation for ten minutes. Refreshing a list invalidates its previous numbers; restart loses the shortcuts. Explicit commands select an identity from that snapshot and recheck the live owner before acting. Bare numeric messages remain ordinary model input.
