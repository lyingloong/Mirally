# Mirally 功能与体验验收清单

> 本文下方保留 OpenClaw 维护基线的人工体验清单。`codex/mirally-framework-refactor` 默认入口现已运行自有框架，Mirally 自有体验按 [新框架迁移对照](framework-experience-migration.md) 保留；涉及上游配置路径、Gateway、原生 Files 等操作以新文档为准。旧入口需显式 `--openclaw`，不要与新 owner 同时运行。

更新日期：2026-10-15。用于对照检查这几轮累计增加的功能，也用于记录尚未解决的体验问题。所有方框留给实际使用者勾选；有过机器侧验证，不等于你的桌面体验已经验收通过。

当前检查入口是项目根目录的 `.\run.ps1` 或 `.\run-openclaw.ps1 mirally`：完整原生工作台，加上 Mirally 的品牌、工作页面和侧边伙伴。旧 UFO 专用界面和独立 Tk 客户端已删除，不再维护第二套界面。普通会话使用主 Agent，UFO 仅承接其委派的桌面子任务。

## 本轮优先检查

你刚反馈的问题与改动列在最前面，修复效果待复测：

- [ ] **任务随新命令更新**：在同一会话连续发送两个不同请求，再进入侧边伙伴。标题应显示最新已发送请求，步骤属于当前回合；未发送草稿和旧任务的工具记录不替换它，会话历史刷新时也不闪回待命。
- [ ] **模型接收图片**：在「设置 → 模型」选择实际支持图片的模型，确认「支持图片输入」已开启；重新附上一张有明确文字和图形的图片，请助手描述并核对结果。开启能力不会自动截屏，旧请求中被省略的图片需要重新附上或读取。
- [ ] **回复主动冒出**：在桌宠小输入里发送「你好呀」，发送后移开鼠标。完整回复到达时应自动出现消息气泡，直接显示回答，不必先点「查看工作进展」；任务结束也应主动显示结果。
- [ ] **直接进入开屏**：第一次显示窗口时已有开屏动画，不先出现一整页深色空窗；准备失败时仍能看见错误提示并从「窗口图标 → 重新连接」重试。
- [ ] **主页品牌精简**：左上角只保留页面内的一个 Mirally；标题栏不显示品牌文字，下面没有独立「⋯」菜单行。点击标题栏左上角窗口图标或按 `Alt+Space` 可打开原生系统菜单，原应用功能与标准 Windows 窗口菜单项可用，窗口按钮及任务栏图标保留。
- [ ] **侧边伙伴首次出现**：启动后不把鼠标移到屏幕右侧，直接点击「侧边伙伴」。预期立即看见有图标与状态的伙伴窄栏，不出现白色空白块，也不依赖悬停才显示。
- [ ] **入口不会随会话消失**：新建会话、打开旧会话、连续切换几个会话。预期「侧边伙伴」与「工作」入口一直可找到；页面暂时加载时也不能永久丢失入口。
- [ ] **真正的工作页面**：进入与「对话」并列的「工作」页面。预期有可选任务卡片、材料区与要求编辑，选择任务只进入准备界面；不再弹出旧「办公起步」选项后把整段提示词塞进对话输入框。
- [ ] **未发消息也能使用**：刚打开原生新会话页面，不先发送「你好」或占位消息，直接进入「工作」或「侧边伙伴」。原有草稿与附件应保留，不自动发送。
- [ ] **三种形态各有用途**：侧栏直接显示工作步骤，悬停才开详情；48 px 图标悬停仅开小输入气泡；伙伴悬停挥手、左击爱心，右键才出现操作菜单，不再都开大面板。
- [ ] **宠物造型与动作**：伙伴默认是蓝色小海獭，也可选小飞狐，没有矩形卡片底色；闲时呼吸、眨眼，工作、等待与完成各有动作。展开后仍能看见它，点一下会回应。

原生未发送的新会话入口已重新通过 10 项机器侧检查；丰富工作页面通过 27 项真实 GUI 检查，22 项 Python 与 18 项 JavaScript 自动检查通过。浮窗宿主白底已修复，并在真实 Windows 桌面验证侧栏、图标、伙伴和展开面板四种显示：外部区域透出背景、点击命中下方窗口，前台焦点未改变；恢复工作台后窗口样式和背景也正确还原。这些不代替你的体感验收，方框仍留给你检查后勾选。本机证据分别在 `output/openclaw-native-verification/new-page/verification.json`、`rich-work/verification.json` 与 `desktop-clip/result-*.json`（后两者同属该验收目录）。

## 1. 品牌、启动与助手身份

**展示位置**：启动页面、窗口与任务栏图标、工作台头像、主题设置、助手回答。

**检查步骤**：退出并重新打开窗口；查看启动过程；进入工作台后分别查看浅色与深色模式；新开会话问「你是谁？你的名字有什么含义？」。

**预期表现**：

- [ ] 启动页使用正式的蓝青渐变「相伴 M」图标，标语为「与你并肩，让想法向前。」；环绕光带、柔光与粒子动画持续播放，等待稍长也不会停成静态空白。
- [ ] 工作台准备好即进入，不为了播完动画额外等待；失败时有可操作的重试提示。
- [ ] 主要界面显示 Mirally，默认主题为晴空蓝，深色模式为蓝灰底色与浅蓝强调；主题与头像风格一致。
- [ ] 默认头像与工作状态使用正式图标；上游推广卡片不占界面，渠道的实际功能仍保留。
- [ ] 助手知道自己叫 Mirally，含义是 MIRA + ally、与你并肩工作的 AI 伙伴，不再要求用户先给自己取名；询问模型与底层技术时应如实回答。

旧版首次显示通过自有 WebView2 检查：开屏就绪前隐藏、首帧后显示、动画与错误提示正常，标题为空，当时顶部菜单为「⋯」，图标、任务栏及同一窗口句柄保留。临时透明度恢复后不残留分层窗口标志；当时相关 20 项 Python 回归通过。历史证据在本机 `output/openclaw-native-verification/verify-startup-first-paint.json`，不代表当前窗口图标菜单已通过体验验收；上述方框仍留给实际启动验收。

## 2. 完整工作台、对话与设置

**展示位置**：主窗口的原生导航、会话列表、对话内容、工具记录与设置页面。

**检查步骤**：进行普通问答；让助手读取一份本地材料；打开会话历史与设置；切换主题并将窗口最大化、恢复、最小化。

**预期表现**：

- [ ] 普通问候和问题能正常对话；执行请求使用合适的工具，不把每句话都变成控制鼠标的任务。
- [ ] 会话列表可直接选择，会话正文、附件、工具记录与结果可以完整查看。
- [ ] 原生模型、工具、权限、Agent、渠道、插件、记忆与调度等入口保留；Mirally 的外观不会挡住这些功能。
- [ ] 最大化后内容正常利用窗口空间；浅色与深色切换、首次最大化时没有明显白屏闪烁。
- [ ] 最小化后能从任务栏找到并恢复窗口；恢复后仍在原来的会话。

这里的“保留入口”不代表所有第三方服务都已经配置成功。具体未配置、未验收范围见最后一节。

## 3. 与对话并列的工作页面

**展示位置**：主窗口的「工作」入口；侧边伙伴中的工作入口可返回这里准备任务。

**检查步骤**：选择下表中的工作起点；添加材料、修改侧重点、要求与交付方式；切换任务或返回对话，再回来查看；最后主动发起一次工作。

| 工作起点 | 准备方式 |
| --- | --- |
| 整理会议 | 会议记录、文件，可选会议纪要/行动清单/核对分歧；可添加音视频，不保证当前服务已能转写 |
| 准备汇报、打磨文稿、从想法写起 | 直接粘贴文稿或写想法，指定受众与表达侧重 |
| 比较方案 | 填写方案背景，选择综合、成本、效果或风险侧重 |
| 读懂材料 | 带入文件，选择抓重点、逐项核对或回答问题 |
| 网页研究 | 每行填写一个网页网址，或拖入链接，说明研究目标 |
| 看图与截图、一起看页面 | 添加图片，或用专用手柄拖向目标窗口；先看预览再写要求 |
| 其他工作 | 自由填写目标和材料，可先讨论或继续推进 |

**预期表现（本轮改版待验收）**：

- [ ] 工作页面与对话之间可以切换，原生侧栏仍可使用；会话列表与其他设置不被工作页面遮住。
- [ ] 每张任务卡片说明能帮你做什么；点选后进入独立准备布局，继续添加材料和要求，不会立即执行；「换个起点」能返回卡片列表。
- [ ] 材料可以拖入或用文件选择器添加；材料列表可见，读取/上传状态明确，失败时有提示。
- [ ] 不同工作呈现相应准备方式：文稿/想法与受众、网页链接、图片预览、窗口截图手柄，以及相应侧重点选项，不只是相同表单换标题。
- [ ] 任务要求可编辑，交付方式可选「可编辑文档」「表格与清单」「先在对话中看」「展示初稿」。前两项保存 Markdown，展示初稿保存可在浏览器打开的 HTML，不冒充 Word、Excel 或 PPTX 文件。
- [ ] 选择任务不改对话中的文字草稿；工作要求在当前页面的各会话内分别保留，来回切换后不串会话，也不承诺刷新页面后仍保留。
- [ ] 「开始这项工作」成功提交后显示原生对话，原有文字草稿仍在；已发送的材料和工作表单从准备区清理，可再切到侧边伙伴查看工作，不形成第二套会话记录。
- [ ] 材料和要求都为空时不能开始；读取中或失败的材料有明确状态，等待就绪或重新添加后才能提交。发送未被接纳时保留要求和材料，不显示虚假的执行成功。

## 4. 后台工作，不占用你的鼠标

**展示位置**：对话中的工具活动、实际输出文件，以及你同时使用的其他应用。

**检查步骤**：提供一份无敏感信息的本地文本或 Markdown 文件，让助手读取并另存摘要；任务期间正常使用其他应用。再试一个公开网页读取请求。

**预期表现**：

- [ ] 读取、写入和命令处理能在后台完成，你可以继续移动鼠标、输入和操作其他窗口。
- [ ] 对话里的工具记录与真实操作一致；输出文件确实存在，并且内容来自指定材料。
- [ ] 公开网页可通过网页读取或独立浏览器处理，不默认使用你的鼠标和当前浏览器窗口。
- [ ] 关闭 Mirally 窗口后后台任务仍能继续；重新打开后可回到同一会话查看状态与结果。

文件、命令、公开网页读取和独立无窗口浏览器已有机器侧验证，你也曾反馈后台工作没有干扰。关闭窗口保留后台服务；关闭电脑或结束后台服务则不能保证继续。

## 5. 侧边伙伴的收起、展开与窗口操作

**展示位置**：屏幕边缘的侧栏、48 px 图标或 80×96 px 伙伴，以及各自的详情、输入气泡或右键菜单。

**检查步骤**：空闲时进入侧边伙伴；反复移入、移出；在输入框写一段未发送文字；最小化后恢复；返回完整工作台。

**预期表现**：

- [ ] 初次进入即可看见伙伴；没有白块、空壳或必须悬停才出现的情况。
- [ ] 侧栏为约 80×300 px，距屏幕边缘约 4 px；工作时不必悬停就能看到状态、当前步骤和最近已处理。悬停才显示约 376×560 px 详情。
- [ ] 图标为约 48 px，悬停只出现左侧约 248×148 px 小输入气泡，本体仍独立可见；点击进入输入，气泡可添加文件、↗查看详情、×关闭。
- [ ] 伙伴约 80×96 px；悬停只挥手，左击只给爱心，不自动开面板。右键出现约 220×252 px 菜单，「说一句」开小输入，「查看工作进展」开详情，也可回完整工作台或选择形态/造型。
- [ ] 在伙伴上松开右键能打开菜单；网页处理丢失时有 WebView2 原生菜单请求兜底，原菜单事件与键盘入口仍可用。
- [ ] 松开右键后菜单完整显示，不只闪过宠物左侧一条竖线；鼠标能进入并点击菜单，进入菜单后不立即消失。
- [ ] 本体、气泡与菜单之间的约 8 px 间隙和外部区域透明、点透；从本体移到输入气泡时不闪烁或误收起。
- [ ] 伙伴轮廓内的透明空隙没有黑底；小输入和菜单周围保持透明，详情和完整工作台恢复正常不透明背景。
- [ ] 实际输入或用键盘操作时保持展开；未发送草稿不会阻止收起，重新展开仍能看到草稿和附件。只是悬停不会抢走其他应用的输入焦点。
- [ ] 展开后的减号有清晰悬停反馈，作用是最小化到任务栏；恢复后伙伴仍可用。
- [ ] 「打开完整工作台」恢复正常窗口，当前会话、草稿和附件保持一致。
- [ ] 选择「侧栏」「图标」「伙伴」后收起到对应形态，重开窗口沿用选择；图标和伙伴直接拖动本体可移动位置，不因悬停出现气泡而误拖正文。
- [ ] 图标保留正式相伴 M，天蓝色柔光底座与状态点在浅深主题下清晰；伙伴默认使用手绘矢量小海獭，也可选择小飞狐，外部区域透明。
- [ ] 伙伴右键菜单或显式详情中可选「小海獭」「小飞狐」，选择后收起；改为狐狸后重开仍保留，草稿与附件不丢失。
- [ ] 展开面板仍显示伙伴；悬停挥手，点击伙伴给出爱心回应。工作、待确认、完成动作来自实际会话状态；动画不代表编造的进度或替你执行了操作。
- [ ] 键盘可进入相应输入/菜单功能；实际输入焦点或键盘操作保持界面，Esc 或×可主动收起，草稿本身不锁展开。启用「减少动态效果」后保留功能。
- [ ] 拖动展开面板的顶部空白、名称或标志即可调整位置；位置手柄「⠿」与 Alt 拖动仍可用。功能按钮和宠物点击不会被当成移动，收起的图标/伙伴也可直接拖动。
- [ ] 浮窗顶部没有菜单黑带；通过「收起浮窗」可主动收起，减号仍是最小化；返回工作台后正常窗口恢复，点击标题栏图标或按 `Alt+Space` 仍可打开菜单，没有独立菜单行。

当前默认小海獭，可选小飞狐；「相伴精灵」保留为未接入概念。造型选择只记在此桌面页面来源的 WebView 配置档中，不是 Gateway 设置，也不是助手记忆。生成方式、矢量来源与动作说明见[设计记录](design-concepts/mirally/desktop-pet/README.md)；原小飞狐与小图标的[概念预览](../output/imagegen/mirally-companion-pet/index.html)保留为历史探索。应用正式标志仍是相伴 M。

此前三种形态通过 35 项 WebView 交互检查和浅深主题共 14 组布局检查，另在自有 Windows 测试宿主核对透明、窗口恢复及间隙点透；证据在本机 `output/openclaw-native-verification/three-modes/verification.json`、`three-view-layout/verification.json` 与 `native-menu-clip/verification.json`。其中 `native-menu-clip` 是旧 MenuStrip 版本的历史验证，不代表当前窗口图标菜单已通过体验验收。工作状态用合成数据、发送用本地回调验证，不宣称已完成真实模型任务。上述方框保持未勾选，实际应用切换、自然拖动与动画体感仍需核对；`compact-flow/verification.json` 属于此前全模式悬停开大面板的历史版本。

此前右键兜底的 14 项网页与 6 项原生事件检查仅证明事件路由。针对“左侧竖线一闪”的动画越界修复，现已验证首帧裁剪扩展、菜单/按钮原生命中、选择狐狸后收起及图标小输入命中，证据在 `output/openclaw-native-verification/menu-short-trace/trace.json`，旧版对照为同目录 `baseline.json`。测试没有移动系统鼠标，真实鼠标与长期悬停仍待你检查。黑底生产像素证据见 `pet-alpha-fixed/verification.json`（同一验收根目录）；手工框留空，详见[套壳说明](openclaw-desktop-shell.md)。

### 回复与任务结束提醒

- [ ] 桌宠、图标和侧栏都能主动显示当前会话的新最终回复；长内容可滚动，点击「查看完整回复」回原生对话，点击「接着聊」打开共享输入框。
- [ ] 气泡不抢其他程序的输入焦点，移开鼠标或切到其他应用后仍保留；× 或 Esc 可关闭。重复状态更新不反复弹出，下一轮即使回答文字相同也会再次提醒。
- [ ] 正在写补充要求、有未发送附件或正在操作菜单/详情时，原交互保留；收起后可看到本轮待查看的气泡。开始新工作后旧气泡退出。
- [ ] 重开窗口、切换会话和加载旧历史不会把已有回答当新回复；工作中的说明、待审批、失败或取消不显示为成功结果。结束事件先到而正文晚到时，同一个气泡更新正文，已关闭的气泡不重新弹出。

提醒只跟踪当前展示的原生会话，其他会话继续使用原生后台状态入口。机器侧行为与原生窗口检查的范围见[套壳说明](openclaw-desktop-shell.md)，实际模型回复、鼠标与应用切换体感仍由以上方框核对。

### 把材料交给伙伴，或带回一个窗口画面

**展示位置**：伙伴图标/面板的拖入区、独立的「◎」截图手柄，以及工作页面的「把 Mirally 拖向要看的窗口」手柄。移动伙伴与拖向窗口采集是两种操作。

**检查步骤**：分别拖入文件、图片、文字和浏览器链接；再从专用截图手柄拖向另一个窗口，松开后检查材料预览，填写要求，再主动发送。

- [ ] 拖入只准备材料，不自动执行或发送；网页链接、文字、图片和文件都能核对后再使用。
- [ ] 普通材料拖入后进入小输入或侧栏详情准备要求；显式窗口截图完成后打开详情核对图片，避免截图藏在小图标里。
- [ ] 专用截图手柄需要明确拖动（至少约 8 px），普通点击、悬停和移动伙伴位置不会自动采集窗口。
- [ ] 窗口画面作为截图附件预览；先核对截图和目标，再填写需要助手做什么，最后主动发送。
- [ ] 若提示只带回可见区域，检查遮挡是否混入画面；截图错误、空白或不完整时重新采集，不把错误画面当成目标窗口内容。
- [ ] 截图不代表实时操作授权，也不会自动读取浏览器整页 HTML 或网址。需要后台阅读网页时，另行拖入或填写网页 URL。
- [ ] 切换会话后尚未返回的截图不会错投到另一会话；未发送的截图不被额外持久保存到项目目录。

窗口采集到原生附件、再到工作台与伙伴双预览的完整链路，已用本机合成窗口通过 11 项检查：480×320 图像尺寸与像素匹配、标题正确、未发送不产生工作回合，前台焦点不变。证据在 `output/openclaw-native-verification/context-handoff/verification.json`。这不代表各种真实应用都兼容，仍请检查自己的窗口。工作表单与源截图只是页面内的临时准备材料，刷新或关闭前请注意未发送内容。

本次发现默认模型条目缺少 `input` 声明，会话工具结果明确显示 OpenClaw 在请求前省略了图片。官方定向补齐 `input: ["text", "image"]` 后，有效模型目录已回读为 `text+image`，其他配置保持一致，Gateway 已热加载模型变更，无需重启。证据在本机 `.artifacts/model-vision-verification/repair.json`。模型设置的能力开关已通过离线界面验证；本次未调用模型 API，实际识图表现仍按上方项目核对。

## 6. 动态进展与运行中补充

**展示位置**：伙伴窄栏的动态状态、展开面板中的当前工作与近期步骤、底部输入区、完整对话历史。

**检查步骤**：发起一项持续一段时间的文件工作，展开伙伴查看进展；在任务仍运行时发送明确的新要求，例如改变汇报受众；完成后核对结果。

**预期表现**：

- [ ] 工作中窄栏与展开面板都有持续工作的视觉反馈，展开不表现得像暂停了。
- [ ] 工作步骤来自实际活动，例如读取资料、整理文件或处理网页；不显示编造的百分比或虚构步骤。
- [ ] 侧栏当前步骤属于当前运行，最近已处理单独显示；已结束的旧运行步骤不会冒称当前还在执行。
- [ ] 不必停止任务就能输入和发送补充；发送时有反馈，原生对话历史中能找到该条消息。
- [ ] 最终结果确实采用补充的新要求；若任务已经结束，消息作为后续修改处理，不能算作中途调整通过。
- [ ] 发送失败时能看见提示并找回草稿；点击发送或收到接收确认不能冒充任务完成。
- [ ] 「停止本轮工作」使当前助手回合停止，并显示对应状态；已产生的回复和文件仍可查看。

真实活跃任务中的补充已有单独验证。任务尚在准备、模型回合未开始时发送的信息，可能按原生机制排为后续回合。停止助手回合也不意味着所有外部子进程都一定退出。

## 7. 附件与材料共享

**展示位置**：工作页面材料区、伙伴的文件区、原生对话输入区。

**检查步骤**：添加两份有明显不同内容的材料；在工作台与伙伴之间切换；发送后要求同时引用两份材料。

**预期表现**：

- [ ] 点击添加与拖入都能看到文件名称及准备状态，不只是把文件名写进消息。
- [ ] 切换显示形式后材料仍在同一会话，不丢失、不重复、不串会话。
- [ ] 结果确实使用两份材料；读取失败、格式不支持或信息不足时说明原因。

先用 [会议纪要](demo/meeting-notes.md) 和 [项目背景](demo/project-background.md) 检查，再尝试自己的 PDF、DOCX、XLSX。合成 Markdown 已验证，其他格式仍需逐类确认，不能因一次 PDF 解析成功就认定所有办公格式都已验收。

## 8. 清晰交接、真实成果与不确定项

**展示位置**：任务结束后的伙伴交接区域，以及固定的「查看回复」「补充确认」「查看成果」入口。

**检查步骤**：使用两份演示材料完成汇报，材料里包含时间、预算与负责人分歧；查看交接，再打开实际输出文件。

**预期表现**：

- [ ] 明确交接的回复分成「待你确认」「助手已完成」「下一步建议」，待确认事项优先展示；普通回答仍是回复回顾，不硬凑三段。
- [ ] 材料分歧、缺失信息和未批准事项如实保留，助手不会擅自定日期、预算或负责人。
- [ ] 长回复不会把查看完整回复与成果的入口挤走；「查看成果」进入原生文件/工作区面板。
- [ ] 文件能实际打开，内容与回复所述一致；仅有一句“已保存”和一个路径不算交付成功。
- [ ] 伙伴列出的文件属于当前会话；不会把会话里已有的文件都说成本轮刚生成。
- [ ] 点击「补充确认」后可编辑自己的决定再发送，已有草稿保留；不会自动发送或代你批准。

伙伴只展示原生已识别的文件/产物，命令生成的文件可能没有自动登记。没有条目时仍应能查看完整回复与工作区。

## 9. 需要你决定时的交互

**展示位置**：伙伴的「需要你」状态与「查看需要你决定的事」，完整工作台的原生问题/权限审批界面。

**检查步骤**：在自然使用中遇到真实问题或权限审批时，从伙伴打开工作台并处理，然后观察窗口状态。

**预期表现（真实人工流程仍待验收）**：

- [ ] 伙伴明确提示需要你查看，不把待处理问题隐藏在一般工作状态里。
- [ ] 打开后可以正常点击和回答，界面不会僵住或失去交互。
- [ ] 处理完后能回到伙伴视图，工作进展仍在；不一直停在一个无法操作的普通窗口。
- [ ] 交接中的「待确认」与工具权限审批清楚区分；「补充确认」不会绕过权限审批。

不用为测试制造不必要的外部发送、采购或其他真实操作；遇到实际审批再记录结果即可。

## 10. 会话延续、近期会话与其他后台工作

**展示位置**：完整会话列表，伙伴的「接着上次」「最近会话」与其他后台会话提示。

**检查步骤**：在会话里说一个临时项目名称与要求，重新打开后追问；用「接着推进」准备下一步；建立另一会话并切换回来。

**预期表现**：

- [ ] 同会话中能延续之前的上下文，重连后仍能接上，不强制只保留六轮。
- [ ] 「接着上次」展示已有进展；「接着推进」准备可编辑消息，不自动执行下一项工作。
- [ ] 近期会话可直接点选，选中状态明确；切换后标题、状态、附件和结果属于所选会话。
- [ ] 原生已加载的其他会话在工作或需要查看时，伙伴有相应提示，点击能进入对应会话。
- [ ] 开新会话、打开旧会话后「工作」和「侧边伙伴」入口仍可找到。

近期列表是快捷入口，完整历史仍在工作台；它不是六轮上下文限制。伙伴的跨会话提示也不是独立监控所有任务的服务，未加载会话不保证全部出现。会话内上下文已验证；跨会话自动记住所有信息并不在此范围。
