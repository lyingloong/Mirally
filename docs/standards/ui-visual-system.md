# Mirally 排版与视觉基线

更新：2026-11-06，Asia/Shanghai。状态：现行。沿用已有的蓝色品牌、明暗主题、布局、伙伴与动效，统一文字的角色和阅读节奏。交互规则见 [UI 规范](ui-guidelines.md)。

## 方法与依据

- [Fluent 2 排版](https://fluent2.microsoft.design/typography)使用有明确角色的字号层级；[布局](https://fluent2.microsoft.design/layout)用间距表达内容关系。采用这套方法，不复制其全部数值或品牌。
- [Windows Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography)强调平台字体、Regular/Semibold 及语言回退。Mirally 默认明暗主题使用系统字体，简体中文显式列出 Microsoft YaHei UI/微软雅黑，跨平台保留苹方和 Noto Sans CJK 回退；字体只从本机和已有资源读取，不新增在线字体依赖。其他主题和用户手动选择保留。
- [Carbon Type Sets](https://www.carbondesignsystem.com/building-blocks/foundations/typography/type-sets)区分操作密集的 14px 和阅读展示的 16px 基准。因此聊天正文与导航、设置标签采用不同角色，而不全局机械放大。
- [Codex 官方界面示例](https://learn.chatgpt.com/docs/features)和[发布介绍](https://openai.com/index/introducing-the-codex-app/)用于观察内容优先、分组导航和按需展开操作的组织方式；不能从截图猜测其精确字体或像素值。同仓 DSH 的 [字体角色](../../kernel/dsh/packages/client/ui-theme/src/theme-settings.ts)、[字体回退](../../kernel/dsh/packages/client/ui-theme/src/styles/base.css)及[对话宽度轴](../../kernel/dsh/packages/client/ui-conversation/src/client/skeleton/ConversationRoot.module.css)作为源码参照：正文/代码/终端分工，正文与输入区保持共同边距；窄窗优先保护内容。本轮复用 Mirally 现有会话布局，不将这些 DSH UI 源码视为当前界面的实现，也不直接照搬其较小的代码字号。
- [WCAG 文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)和[对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)用于验收：普通文字与背景至少 4.5:1；放大后仍能读取内容、使用操作。不是以某个字号、截图或单一比例宣称整个产品符合 WCAG。

## 当前文字角色

以下为 Mirally 默认 100% 文字大小的产品选择，不是外部标准要求。用户指出初版整体字号偏大后，采用这套紧凑密度，通过字重、行高和留白组织层级。

| 用途 | 字号 | 行高 | 现有 token |
| --- | --- | --- | --- |
| 时间、来源、短辅助标记 | 12px | 按组件，通常 1.4–1.5 | `--control-ui-text-xs` |
| 设置说明、状态、次要控件 | 12px | 设置 1.5，阅读说明 1.6 | `--control-ui-text-sm` |
| 导航、设置项、按钮、列表与问题正文、日志 | 13px | 1.45–1.65 | `--control-ui-text-md` |
| 分组与内容标题 | 14px | 1.45–1.5，600 字重 | `--control-ui-text-lg` |
| 聊天正文 | 14px | 1.65 | `--chat-text-size` |
| 对话编辑器（桌面） | 14px | 1.5 | `--control-ui-text-lg` |
| 页面标题 | 22px | 1.35，600 字重 | `--control-ui-text-title` |

特殊标题、配对码可有独立角色，但仍乘 `--control-ui-text-scale`。已有“外观 → 文字大小”继续生效，不增加第二套字号设置。代码保留等宽字体，常规中文说明使用界面字体；不能只给普通长文换上等宽字体来制造层次。

对话编辑器使用 `--control-ui-text-lg` 的字号值，保持正文输入的常规字重；桌面默认 14px，随用户文字大小缩放，不再被统一的 16px 下限放大。触屏输入保留至少 16px 的下限，同时继续使用该缩放 token；编辑器行高与字号联动。这里区分对话编辑器与下文的 13px 设置输入，不改变聊天正文的独立文字角色。

## 默认明暗主题的配色角色

默认 Mirally 主题使用同一套中性色阶组织背景、表面、文字和边界，蓝色品牌用于交互重点。配色按角色维护在共享 token 中，避免各区域分别叠加蓝灰底色和透明混色，导致同一页面出现不一致的色偏。

| 角色 | 明亮主题 | 暗色主题 |
| --- | --- | --- |
| 主内容画布 | 白色 | 深中性灰 |
| 侧栏与次级表面 | 浅中性灰，与画布轻度区分 | 中性灰，靠明度区分层次 |
| 输入区、菜单与浮层 | 清晰的不透明白色表面 | 清晰的不透明深灰表面 |
| 正文与辅助文字 | 深灰正文、可读的次级灰 | 浅灰正文、可读的次级灰 |
| 分隔、悬浮与普通选中项 | 同色阶灰色边界和表面变化 | 同色阶灰色边界和表面变化 |
| 主操作、链接与焦点 | 蓝色强调 | 适配暗色背景的蓝色强调 |

普通用户消息气泡沿用中性表面，不把大面积蓝色作为默认身份区分；显式发送者身份 tint 保留。输入区避免依赖半透明混色形成常态背景；聚焦、录音、错误等状态仍需有明确反馈。成功、警告与危险等语义色继续表达各自状态，不受品牌蓝色限制。

这些原则限定默认明暗主题，其他可选主题、用户主题选择、伙伴资源和系统强制颜色模式继续保留。文字、控件和焦点仍按相关对比度要求及实际页面验收，不能只凭色值表宣称全界面可用。

## 组合规则

1. 优先复用 token。新页面不散落 11/12/13px 等固定值；已有硬编码按相关页面逐步修正，不盲改图标、头像、二维码和装饰尺寸。
2. 正文和中文标题默认正常字距；字号、字重、行高和间距共同表达层级。不要用全局负字距、全大写或极浅颜色把中文挤成细小的标签。
3. 沿用 4/8/12/16/24/32/40px 间距档位，紧密相关的标签与说明使用 2px 微间距；相关操作靠近，分组之间留白，不为美化增加嵌套卡片和大面积装饰。
4. 设置控件保留紧凑的 32px 基准，并随文字缩放增长。触屏保留原有更大目标；布局通过换行或堆叠适配，不靠缩小文字或裁掉按钮。
5. 不同类型页面可以有不同密度，但相同角色须一致。检查运行时晚加载的活动、记忆和伙伴样式，不能只修改基础 CSS 就声称全产品已统一。
6. 在真实页面检查默认与放大文字、长中文与中西混排、深浅主题、窄窗口、错误和密集列表。保留用户草稿与操作状态；视觉调整不修改权限、会话或模型语义。

本轮覆盖主窗口共享排版、对话、设置、工作列表，以及实际加载的活动与记忆页面；伙伴的特殊窗口几何与动画继续沿用现有实现，其独立密度需结合原生窗口后续验收。

2026-10-29 设置补查：桌面输入与原生下拉使用 13px 界面文字，选项继承字体；不能由遗留的 16px 输入最小值覆盖整套桌面排版。触屏仍沿用至少 16px 输入以避免移动浏览器自动放大。外观选择、主题导入、字体菜单和设置导航使用相同语义 token；普通偏好内容使用界面字体，结构化 JSON 保留等宽字体。隐藏的控件标签不得留下占位边距，造成同排输入与选择器高度不一致。
