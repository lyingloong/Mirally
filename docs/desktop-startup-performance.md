# Mirally 桌面启动耗时

2026-10-04，在本机 Windows、Node 24.21.0、OpenClaw 2026.9.6 下测量。计时从 Python 进程开始，到原生工作台连接成功、Mirally 入口可用；不包含模型回答时间。

## 定位结果

后台 Gateway 已运行时，修改前完整启动测得约 19.1 秒：

| 阶段 | 耗时 |
| --- | ---: |
| Python、WinForms 和 WebView2，直到开屏页面加载 | 2.49 秒 |
| 完整 `dashboard --json` 命令 | 15.46 秒 |
| 品牌脚本注册 | 0.035 秒 |
| 导航后工作台连接可用 | 约 1.09 秒 |

入口没有加载旧 UFO、Torch 或 Tkinter。网页资源和 Mirally 品牌脚本也不是此次主要瓶颈。

另行连续测量完整 dashboard 命令，耗时约 11.8～13.8 秒。其时间包含通用 CLI 启动与路由、配置加载、Windows 服务与端口诊断、RPC 就绪检查、原生一次性登录交接。

## 修正

`integrations/openclaw/dashboard.mjs` 直接调用已安装包导出的官方 `dashboardCommand`，使用其 JSON 模式。函数本身及其中的配置解析、服务检查、原生登录流程保持不变，减少完整 CLI 的启动与路由成本。没有拼接长期令牌 URL，也不缓存一次性登录链接；命令结果由 Python 私下读取，不写入公开日志。

这个入口只适配固定的 2026.9.6。包版本、唯一入口或函数导出不匹配时，桌面宿主回退完整 CLI。普通 `run-openclaw.ps1` 命令继续走官方 CLI。

桌面窗口初始化与原生入口准备并行进行。开屏尚未就绪时暂存状态，就绪后显示；取得入口且页面准备好后才注册皮肤并导航。启动动画不额外延长已经达到最低展示时间的等待。

## 复测与范围

相同后台服务下，两次完整启动测得 **8.21 秒、8.33 秒**；原生入口约 **7.43 秒、7.40 秒**，与约 2.5 秒的开屏初始化重叠。原生配置加载约 1.2 秒、Windows 服务与端口/RPC 检查约 4 秒仍保留。25 项 Python 和 22 项 JavaScript 检查通过，覆盖版本回退、真实上游函数、原生 JSON 结果、错误隔离、并行启动顺序和开屏状态延迟显示。

这是本机、已有 Gateway 的复测，不是其他电脑的固定速度承诺。首次启动后台服务还需要服务自身的冷启动时间；本轮没有为了测量而停止正在运行的 Gateway。新会话首条请求与模型生成的耗时另见[响应耗时定位](response-latency.md)。

本机脱敏时间记录在被 Git 忽略的 `output/openclaw-native-verification/startup/`；导入分析在 `startup-profile/`。这些时间记录不包含原生登录 URL、密钥或模型请求。
