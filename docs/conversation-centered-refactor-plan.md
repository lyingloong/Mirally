# 会话中心重构计划

状态：主体已实施；验收与未覆盖范围以 [框架第一版](framework-v1.md) 及实际测试为准。依据用户对话与 [产品思考记录](product-notes.md) PN-0073～0079。

当前边界：已接入会话后台作业的查询和停止；用户明确要求时，Mirally 运行期间可登记作业结束通知，复用当时启用的桌面和微信提醒渠道。通知登记不跨宿主重启恢复；旧工作专用的持续文件观察未保留，需要时可在会话中按需查询日志或外部系统。日历提醒和定时动作的既有通知独立保留。

## 目标与边界

会话是通用的协作单位：讨论、执行、查看进展、追问和从微信继续，都使用同一逻辑会话和 DSH 历史。不要求用户创建或维护独立的“工作”，也不针对实验或工作另建专门的运行体系；优先复用并完善 DSH 和 Mirally 已有的通用后台作业。脚本运行与日志有自身状态和生命周期，不将会话摘要或模型推测当作实时进度。

原工作台的预设场景保留为快捷入口：帮助准备需求、链接、附件或截图，提交到新会话或用户选择的现有会话，不自动创建工作或引入另一套 Agent。旧工作数据无需迁移，必要时可重建开发数据；仍有价值的能力需要实现与验收，清理范围与实际任务相符，不擅自覆盖私有配置。

## 实施步骤

1. **梳理并确定所有权**：盘点现有 work、work_runs、会话后台命令、DSH 原生 jobs、定时执行、观察来源、审批、通知及其桌面和微信调用方。确定会话与真实资源的关联和统一查询接口；每项能力只保留一个实际执行 owner，不复制进程或日志，不为了旧内部接口增加兼容层。
2. **会话运行与状态**：支持在会话中执行用户要求的命令或脚本，让耗时任务在后台运行、查看真实状态与输出、按需停止，并在需要时通知结果；继续遵守用户设置的动作权限。接入既有 DSH 原生作业及有价值的运行、日志和成果能力，优先统一查询与归属，不为此重写内核执行器，也不强制照搬旧工作专用运行的每一项技术机制。保留明确的运行身份、会话归属、执行/完成/失败/停止/未知与事件时间；同一会话支持继续聊天。进程生命周期按实际实现声明：退出或崩溃后的状态必须可核实，不自动重放，也不假称任务会跨重启继续。会话停止、归档与停止后台运行分别处理，并同步调整现有微信 `/stop` 的实际行为和反馈。
3. **观察、提醒和通知**：优先由通用工具按需读取日志、文件或远程命令输出，不为某个实验强制建立专用监控配置。已有日志/JSON 持续观察仅在确有价值时作为可选能力保留；无法读取或缺少进度依据时如实返回未知。将需要通知的事件关联回会话，沿用用户的桌面/微信通知设置和持久投递，避免重复通知。日历、周期提醒与定时执行继续使用现有独立领域事实，按需关联会话，不自动将普通提醒变成后台执行。
4. **桌面交互**：侧栏以会话为中心，沿用现有视觉、动画、桌宠和导航习惯。会话列表按需呈现真实状态和筛选；运行详情、输出、成果、停止和审批在相关会话中自然可达，不以摘要替代日志。移除独立工作列表与不再适用的创建入口，保留草稿、附件、焦点、会话排序和会话摘要的现有体验。
5. **快捷开始**：将当前藏在工作页的“整理会议”“一起看页面”等入口移到主页或新会话，并复用原有材料选择、拖拽截图和场景配置。用户可编辑需求，明确选择新会话或当前会话；取消旧模板默认强制保存文件和冗长交接，不要求建立工作。提示词简洁，选项对应真实可用能力；窗口截图是一帧，不声称已实时观察或控制。
6. **微信与跨端**：微信助理继续是默认入口，可找会话、看摘要及真实运行/观察状态，按用户要求向原会话委托后续指令；直接会话仍可继续使用。移除或重新设计以工作为前提的命令、工具、文案和通知，不留下不可用入口；自然语言中的“工作进展”正常进入助理，不被旧工作指令路由拦截。可选手机网页也改为会话入口。普通微信回合与桌面沿用相同权限策略，保留绑定和会话归属校验。无需云服务器，电脑和 Mirally 在线是远程操作与通知的条件。
7. **收尾与验证**：删除不再使用的工作模型、界面、渠道入口和测试，更新现行架构、帮助、产品记录及 CHANGELOG；旧数据不迁移，必要时重建开发数据库。验证实际桌面页面、键盘、窄窗口与主题，隔离测试微信和真实 DSH 链路；记录真实 API、微信账号及重启行为尚未实测的部分。

## 验收场景

- 电脑端在普通会话中启动实验，查看真实运行状态和日志；从微信助理找到该会话、询问进度并继续发指令，状态来自实际进程或观察来源。停止回复不应误报实验结束。
- 创建定期检查或提醒，并在关联会话与微信查看其真实规则、状态和投递；桌面离线时不承诺即时执行。结果不明时不重放动作或伪造成功。
- 在快捷入口选择“一起看页面”并提供截图，材料进入选定会话；切换、取消、失败和重试时草稿和附件归属正确，不产生多余工作记录。
- 多个会话的执行中、等待用户和失败状态正确；切换、归档、恢复及重启后不混淆会话、历史、运行和权限。
- 桌面与微信的审批策略一致；解绑、会话变更及取消后，过期回合不得提交动作或投递结果。权限、资料、插件/Skill/MCP 和已有桌宠窗口体验均按实际能力验证。
