# Activity 数据层评估与验收

日期：2026-10-10  
状态：完成历史样本审计与隔离回放；采集内容质量、活动组织和行为理解尚未通过验收

本文保留 2026-10-10 历史样本的审计结论和验收方案。清理后 2026-10-11 的新样本、投影 v2 修复和复验结果见 [新数据检查](activity-fresh-data-review.md)；下文的旧投影缺陷不代表修复后的当前实现。

本轮聚焦三个问题：数据是否真正收集到，是否正确处理和组织，以及处理结果能否让模型和开发者知道用户做了什么。验收终点是有依据地重建用户活动；数据库记录数、处理无异常、查询成功分别只证明链路的一部分。

## 1. 当前判断与证据范围

| 问题 | 当前判断 | 依据 |
| --- | --- | --- |
| 数据是否真正收集到 | 已收集到部分真实内容；完整性和持续覆盖未验证 | 有非空 OCR、UIA 正文、标题、URL 和可校验图片；输入正文、剪贴板及当前采集器修复效果缺少有效样本 |
| 数据是否正确处理和组织 | 存储与检索基础可用；证据关联和活动边界存在已复现缺陷 | 派生层丢失关联、编辑和截断信息；迟到 OCR 可进入错误页面，后台画面被误切段，明确采集缺口未进入活动质量信息 |
| 数据能否说明用户做了什么 | 可展示部分环境和内容；尚不能可靠说明行为过程及结果 | Episode 摘要主要是观察数量；尚无经过已知行为真值验证的动作、变化、结果时间线 |

本轮只读检查现有原始库与派生库，并在临时目录中通过真实 `ObservationStore → ActivityOrganizer → KnowledgeStore` 回放合成记录。没有启动采集器、操作桌面、访问 Gateway 或调用模型。原始库审计前后 SHA-256 相同。

历史原始库为 `.artifacts/activity-monitor/observations.sqlite3`；派生库为 `.artifacts/activity-agent-access/activity-knowledge.sqlite3`。本地审计产物：

- [总体结构与组织统计](../.artifacts/activity-data-assessment/audit.json)
- [采集内容与图片完整性审计](../.artifacts/activity-data-assessment/capture-audit.json)
- [组织层隔离回放结果](../.artifacts/activity-data-assessment/organization-proofs.json)

这些产物不随 Git 上传，记录聚合统计和合成用例结果。历史样本跨越不同实现与配置阶段；发现不能直接视为最新采集器在所有应用上的表现。

## 2. 收集到了什么，缺少什么

| 内容 | 历史样本结果 | 能证明的范围 |
| --- | --- | --- |
| 原始记录 | 286 条；233 complete、44 partial、9 unavailable | 采集记录已落库；complete 不等于内容足够理解活动 |
| 前台与资源 | 62 条前台切换；30 条非空标题，其中 13 条 URL 非空 | 部分窗口和浏览器资源可以识别 |
| UIA | 61 棵树；26 次开启正文，其中 16 棵含 Value/Text；正文开启记录中 20 次 partial、6 次 complete | 部分应用可取结构和正文；需进一步验证目标区域覆盖与截断影响 |
| OCR | 80 个内容事件，54 次 ok、24 次 error、2 次无结果；52 次非空，共 15,897 字符、25 种不同文本 | 有真实识别文本；重复文本和 ok 状态不能证明准确率或内容覆盖率 |
| 输入元数据 | 46 批；207 次键盘计数、6 次点击、6 次滚动 | 有输入发生的证据；没有具体输入内容或操作对象 |
| 输入正文 | 5 条 input_text 全部 unavailable | 此样本没有验证有效的文本变化采集 |
| 剪贴板 | changed、operation、content 均为 0 条 | 未验证此通道；不能据此断定用户没有复制粘贴或实现失效 |
| 图片 | 63 个被引用的 ready PNG 全部存在，大小与 SHA-256 匹配 | 资产可解析且完整；尚需检查画面是否提供有效内容 |

图片均为显示器级捕获。34/63 张图片的黑色像素超过 90%；其中 26 张仍有非空 OCR 且被标记为 complete。黑色比例是内容质量的检查信号，不能单独证明遮罩错误，也不能直接否定剩余区域的信息价值。当前采集代码已有黑帧过滤；旧库缺少对应过滤记录，修复效果需要使用当前版本的已知画面重新验证，见 [丰富内容采集](activity-rich-capture.md)。

样本横跨北京时间 10 月 8 日 00:37–19:00，包含 13 个传感器实例 epoch。各 epoch 首末事件跨度合计约 11.49 分钟；这是记录的跨度之和，不是进程运行时长，也不能作为全天采集覆盖率。判断持续采集需要启停、心跳、明确缺口和策略状态共同提供分母。

286 条记录中，46 条 USER 全部是输入元数据，177 条 UNKNOWN、63 条 BACKGROUND。屏幕出现文字只证明系统观察到了该内容；不能直接认定用户输入、阅读或操作了它。

### 采集验收应回答的问题

- 在声明支持且允许采集的应用、窗口、控件和触发条件下，已知操作是否留下预期内容，而非只有标题或计数？
- 已知中文正文是否能检索到关键短语？OCR 字符误差、UIA 目标区域覆盖和截断分别是多少？
- 已知画面的目标区域是否在图片中可见？图片范围、尺寸、遮罩和来源是否清楚？
- 允许采集的时间范围内是否存在无法解释的缺口？关闭策略、权限限制、unsupported、worker 错误和未发生动作能否区分？
- 图像或原始记录过期后，使用者能否知道证据已不可用？

正文非空率应按启用该通道的预期样本计算，不能用全部 Observation 作为分母。资产哈希、worker 成功、非空文本和真实内容正确性应分别报告。

## 3. 组织层已复现的问题

现有独立派生库、增量游标、来源 ID、稳定 ID 和 FTS 提供了可重建、可检索的基础。但 286 条原始记录对应 286 个 Item，只能说明每条记录经过投影，不能证明多来源证据已经组成用户活动。

| 问题 | 已核实的影响 | 修复要求 |
| --- | --- | --- |
| 关联没有进入派生协议 | 238 条记录有 capture_group，87 条有因果引用；Item/Evidence 未保留这些关系 | 保留原始 kind、capture group、caused_by、时间和身份质量，以及窗口／显示器范围 |
| 迟到结果归属错误 | 页面 A 截图的 OCR 在进入 B 后到达，被加入 B 的 Episode | 优先依据原截图与原资源归属补充证据；无法关联时标记待定，不能借用到达时的前台页面 |
| 编辑语义丢失 | 删除 7 字符的合成输入事件投影后文本和 structured 都为空 | 保留操作类型、删除数量、偏移、控件身份、基线是否已知；动作和正文分开表达 |
| 压缩未标注 | 6,000 字符 OCR 在 Item 和 Evidence 中都变成 4,096 字符，仍为 complete、confidence=1.0 | 分开表达采集质量、派生截断和推断置信度；保留全文的可访问引用 |
| 空间与结构信息丢失 | UIA 控件身份、父子关系、坐标及 OCR 文本块／语言未进入紧凑证据 | 定义保留语义的证据投影，再生成可损的阅读摘要 |
| 活动边界混淆 | 前台窗口只更新标题就切断同一显示器的后台 Episode | 前台访问段与后台画面连续性分别维护；不能把所有 window_context 都当作焦点切换 |
| 明确缺口未反映 | collection_gap 前后活动仍在同一 Episode，活动 data_gaps 为空 | 根据缺口影响范围终止或标记相应活动；缺口期间不推断连续行为 |
| 处理失败缺少持久补偿 | 坏记录计入当次错误后仍推进 checkpoint，没有持久化失败队列或自动重试 | 保留失败来源、原因和重试状态；游标追上不能被视为每条内容都已正确处理 |
| 内容去重不足 | 相同内容、不同来源 ID 仍生成两个 Item | 合并冗余内容表示，同时保留每次观察时间、变化和来源；重复观察不等于重复动作 |
| revision 尚非历史版本 | revision 增加时覆盖同一行，旧版本没有保存 | 明确版本含义；可比较重建结果与修订来源，不宣称旧版本已留存 |

真实样本有 95 个 Episode，其中 42 个时间跨度为零，中位跨度只有 232 毫秒；78 个以 window_changed 结束。这提示分段需要重新验收。瞬时证据簇可以合法存在，但不能据这些跨度计算用户工作时长，也不能把 Episode 数量增加作为组织质量提升的依据。

原始记录仍保留上述被省略的信息。在原始保留期内，改进投影后可重建恢复；本轮没有覆盖现有派生库。

## 4. 什么样的结果才算“知道用户做了什么”

应先形成可追溯的事实时间线，再添加可修订的解释。下表是拟采用的输出契约，并非当前已实现协议：

| 信息 | 最低要求 |
| --- | --- |
| 时间 | 事件发生时间、接收时间和顺序；迟到、时钟或采集缺口明确标记 |
| 对象 | 应用、窗口、资源／文档／URL、控件或画面范围；身份不能确认时说明未知 |
| 观察到的动作 | 前台切换、输入变化、导航线索、复制线索等；保留 actor 和判断依据 |
| 内容与变化 | 关键内容、可确认的插入／删除或前后差异；基线缺失时不虚构差异 |
| 结果 | 只陈述可观察结果；保存、提交、发送、任务完成需有对应证据 |
| 来源 | 每项事实对应可定位的 Observation／Evidence／资产；说明过期或不可用 |
| 质量 | 采集失败、区域缺失、投影截断、关联待定分别表达 |
| 解释 | 任务、目的或跨应用关联作为推断单独输出，附依据与不确定性 |

例如，合成记录明确表示“已知编辑控件删除 7 字符，偏移为 9”，组织结果应保留这些事实。若没有被删正文，就应说明正文未知；若没有保存证据，就不能写成“修改并保存了文档”。只有页面内容出现在屏幕上时，可以陈述显示内容，不能断定用户读完、理解了内容或完成了某项工作。

当前 Episode 摘要主要是“某应用中记录 N 条观察”。108 条语义 annotation 全部来自 generic parser，内容主要是 kind、app、title、URL 和 has_text，且尚未被查询装配读取。模型可能从原文推测活动，但本轮没有进行模型行为理解验证，也没有证据支持其可靠性。

开发者应能直接阅读时间线和检查证据，不必先调用模型才能了解记录含义。模型与开发者应使用同一份事实和质量标记；模型生成的合理叙述不能代替事实验收。

## 5. 验收方法与实施顺序

### 5.1 建立已知行为真值

使用固定中文内容、可识别资源和明确操作步骤建立回放集。每个案例写清支持能力、策略开关、预期来源、已知动作、可确认结果，以及哪些问题应回答“未知”。

| 场景 | 关键验收点 |
| --- | --- |
| 已知网页 A → B，A 的 OCR 迟到 | 页面内容与证据归属正确；不会把 A 的文字放到 B |
| 文档插入、替换、删除，最后有或没有保存证据 | 动作、内容变化、基线和保存结果分别表达 |
| 已知内容复制／粘贴 | 剪贴板变化与用户操作证据分别保留；不会把剪贴板变化自动等同于粘贴 |
| 同窗标题变化、快速焦点切换、跨应用继续 | 同窗更新不伪造焦点切换；跨应用任务关联有依据或保持待定 |
| 多显示器和后台画面 | 范围与来源明确；后台文字不自动归属当前前台应用 |
| UIA unsupported、OCR 失败、截断、暂停或 collection_gap | 应收集而未收集的内容计入失败；未知与缺口明确，不补写连续行为 |
| 重复回放、处理器重启、证据过期 | 幂等、来源可追溯、版本可比较；过期证据不被声称为仍可访问 |

组织测试可全部使用隔离合成记录。当前 Windows 内容能力的后续验证可沿用 `tools/verify_activity_content.py` 的已知自有测试窗口，按 GUI 验证顺序单独运行；历史库无法替代新版本实采验证。

### 5.2 分别报告三组结果

本文件是验收方案，尚未冻结各应用场景的具体延迟、正文准确性和区域覆盖门槛。执行前应填写下表，依据声明支持的能力和内容用途设定门槛；缺少预期内容或门槛的案例只能用于探索，不能报告为验收通过。

| 验收组 | 执行前固定的内容 | 通过要求 |
| --- | --- | --- |
| 采集 | 目标应用／控件、策略、触发条件、必需字段与关键短语、目标画面区域、允许延迟、准确性和区域覆盖门槛 | 必需证据全部出现，内容与来源正确，并满足已固定门槛；声明支持的场景未采到内容计为失败 |
| 组织 | 真值中的证据关系、动作、边界、缺口、截断、版本和重复处理结果 | 已知回放错误归属、静默丢失、虚构连续性为零；所有必要引用可解析 |
| 理解 | 每个问题的必答事实、正确来源、预期未知，以及可接受的推断范围 | 必答事实正确且能定位来源；预期未知明确表达；无依据断言为零，推断不混入事实 |

1. **采集**：按通道和支持场景统计预期内容命中、文字准确性、画面目标区域可用性、延迟和缺口；记录未支持能力与失败原因。
2. **组织**：检查证据引用是否解析、资源和动作归属是否正确、迟到关联、边界、截断声明、去重与回放一致性。已知回放案例中的错误归属、静默信息丢失和虚构连续性必须为零。
3. **理解**：对事实时间线进行行为问答，例如打开了哪个资源、编辑了什么、先后做了哪些动作、结果能否确认、哪些部分缺证据。记录正确事实、漏失事实、无依据断言和来源定位；未知问题应明确回答未知。

先验证开发者能依据输出复核已知行为，再独立评估离线模型理解。模型选择、提示词、输入版本和问答结果需要记录，结果不能反向改变真值。

### 5.3 实施优先级

1. **先修证据契约**：补齐关联、编辑语义、范围、时间／身份质量和截断信息，持久记录处理失败；把本轮复现加入组织层回归用例，以新投影版本在临时库对照重建。
2. **再修活动组织**：分开维护前台访问段与后台证据，处理真实缺口和迟到证据；评估内容去重与修订策略。
3. **验证当前采集内容**：建立声明支持的场景矩阵，补齐输入正文、剪贴板、中文内容及有效画面实采证据。
4. **输出可读事实时间线并验收理解**：让动作、对象、变化、结果、来源和未知直接可见，再评估任务解释与模型问答。

通过标准围绕三项数据结果制定。存储、查询和访问入口的工程检查继续保留，各自不能替代内容与行为验收。
