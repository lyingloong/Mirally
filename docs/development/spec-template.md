# 需求规格模板（P0-only）

> 给需求师使用。目标是 **20–30 分钟内产出一份可直接实现的最小规格**，而不是完整盘点。
>
> 更新：2026-11-01 · 状态：active

## 使用规则

- 只写本轮 **P0（必须做）**；P1 可在“后续候选”写一句话，不展开。
- 不重复实现细节；不复制大段现有代码；不写产品愿景。
- 每个改动必须能对应到：触发条件、before/after、文件、测试、验证命令。
- 规格目标约 **100–150 行**；超过则先删减盘点、背景和重复说明。
- 不确定的地方写一条最小风险假设，不等待用户。
- 规格写入 `output/agent-workflow/specs/<dev-id>.md`，并在 state 中记录 `spec_path`。

## 模板

````markdown
# <dev-id> · <标题>

## 1. 点信息

- 来源：user / agent
- 需求来源：user-request / user-seed / agent-seed / existing-seed
- 种子 ID：<如 SEED-README-OPT；无则写“直接需求”>
- 用户原话/来源：<引用用户原话，或说明既有文档/种子依据；不得改变原意>
- 风险：low / normal / high
- 一句话目标：
- 先读：docs/development/requirements-pool.md、docs/development/review-experience.md 的相关条目

## 2. 目标与非目标

### 目标

1. <用户可观察结果>
2. <用户可观察结果>

### 非目标

- <明确不做的事>
- <不改的协议/权限/数据/前端边界>

## 3. P0 改动清单

| # | 触发条件 | 文件:行 | Before | After | 实现要点 |
| --- | --- | --- | --- | --- | --- |
| P0-1 | ... | ... | ... | ... | ... |
| P0-2 | ... | ... | ... | ... | ... |

## 4. 涉及文件（白名单）

```text
path/to/source
path/to/test
```

白名单外如需同步纯断言或必要文档，先在 PR 说明，不悄悄扩大范围。

## 5. 测试与验证

- 最小测试：
  - <成功路径>
  - <关键失败/边界>
- 验证命令（可复制）：

```powershell
<命令>
```

## 6. 假设与风险

- A1：<最小风险假设>
- 风险：<真实环境/未覆盖项>

## 7. 完成定义

- P0 全部落地；
- 目标测试通过；
- 不改变 <明确边界>；
- PR 披露验证与未覆盖范围。
````

## 不放进规格的内容

- 完整文案盘点（放实现或后续审查）
- P1/P2 的逐条 before/after
- 任务流水账、模型选择、团队调度细节
- 与本次目标无关的架构建议

## 完成检查

- [ ] 工程师不需要再询问用户即可实现 P0
- [ ] 每条 P0 都能用一条测试/命令验证
- [ ] 文件白名单明确
- [ ] 规格在 150 行以内，或已说明超长理由
