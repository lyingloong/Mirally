# 日历、提醒与定时执行

更新：2026-10-29，Asia/Shanghai（+08:00）。

在“设置 → 通用”确认日历时区，首次提供系统检测结果作为建议；也可填写其他 IANA 时区。此设置是解释自然语言日期、日历和定时动作的产品时区，不随系统时区变化自动更新。事件保留其实际时刻；日历展示按当前设置的时区，周期动作在时区改变后重新计算。不存在或重复的本地时间需要重新选择。

在会话中告诉 Mirally 会议时间和提醒要求，模型通过日历工具创建事件和提前提醒，成功后才能确认安排。桌面“日历”提供日程和提醒列表、编辑、取消及回到关联会话；微信发送“日程”“今日日程”或“明日日程”，再用“查看日程 1”“进入日程 1”选择。微信侧请求模型创建或修改需开启微信远程控制。

事件及其关联提醒由产品 SQLite owner 管理，一次提醒在到期时原子写入消息页并为启用的桌面、微信渠道分别生成投递。桌面通过本机托盘通知，微信通过已有持久 outbox；渠道状态表示接口是否接受，不能代表用户已读或系统一定展示。账号解绑、来源撤回或事件取消会阻止尚未投递的内容；发送结果未知不盲目重发。渠道开关在通用设置中。电脑联网且 Mirally 保持运行时才能触发，退出、休眠和关机无法保证即时提醒。

“到时提醒”与“到时执行”分开：前者不需要后台模型；后者由产品定时执行 owner 复用 DSH 的时间规则，到期经过原会话命令准入和动作权限。模型可在桌面会话中建立、查询、修改、暂停、恢复或取消；微信暂不开放创建或修改定时执行。支持一次、固定间隔、每日、每周和 cron。会话回复结束后通过提醒渠道提示查看结果，不把一次回复结束当作任务目标成功。不可核实的派发结果停在未知状态，不自动重跑。

暂不支持周期日历事件、外部日历同步或邀请多人；日历扩展可按领域接口后续接入。更新依赖后执行 `./.venv/Scripts/python.exe tools/setup_framework.py` 准备内核，并安装 `requirements-framework.txt` 中的时区依赖。产品数据库升级为 schema 9；不依赖本机用户目录或开发者时区作为产品默认。
