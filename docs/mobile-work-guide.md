# 手机工作与会话使用说明

更新：2026-10-27，Asia/Shanghai（+08:00）。对应本地 Mirally/DSH 框架，不需要 OpenClaw Gateway、UFO 或第二套 Agent。

## 从电脑开始

侧栏“工作”进入真实工作列表 `/tasks`。原“开始工作”准备页、材料、草稿和输出方式保留，提交后关联当前真实会话与工作；列表也可直接交代工作或加入关注。普通聊天不自动变成工作。

- **观察已有工作**：关联 Mirally 工作区内的 JSON 状态文件或文字日志；接口也支持已授权的只读目录。观察不会获得停止外部程序的权限。
- **执行 Python 脚本**：在桌面设置 → 通用开启工作区写入，将实际脚本放入 Mirally 工作区，在工作详情准备运行。核对脚本 SHA-256、参数、目录、预期产物、超时与有效期后，明确批准本次操作。

脚本以当前电脑用户权限执行，目录检查和声明产物不是操作系统沙箱。批准后运行固定核验的脚本内容；导入库及脚本自身的其他效果属于受信代码的能力，不承诺任意 Python 只能操作声明输出。

每次执行保留独立记录。日志最多 1 MiB，下载的已声明、核验产物最多 2 MiB。停止取消实际受监督进程树；结束关注、归档或停止回复不会代替停止程序。关闭到托盘可以继续，超时和明确退出收尾自己管理的任务；异常重启标为待核对，不自动重跑。

JSON 格式示例（由实际程序更新，不代表已有进展）：

```json
{"state":"running","summary":"验证集评估中","progress":{"current":42,"total":100},"metrics":{"loss":0.183}}
```

非法格式/状态或不可访问的来源写入未知和缺口，不延续旧成功状态。日志提供有界末尾摘录。来源约每 30 秒有界轮询，也可主动核对；更新时间是实际观测依据，不推测百分比。

## 配对手机页面

“设置 → 消息渠道”下方增加“手机接入”。服务只监听电脑回环地址，仅开放手机页面、配对和有限操作；桌面管理端口与主凭据不提供给手机。

1. 查看“本机手机服务地址”。同一电脑可预览，手机自己的 `127.0.0.1` 不能连接电脑。
2. 异地使用先配置私人网络 HTTPS 转发，例如 [Tailscale Serve](https://tailscale.com/docs/reference/tailscale-cli/serve)。目标使用设置中实际显示的手机服务源地址，不使用桌面管理端口；先检查现有转发，避免覆盖其他服务。Mirally 不会自动安装网络软件、注册账号或修改转发规则。
3. 把转发产生的 HTTPS 地址填入“私人 HTTPS 地址”。仅支持同一域名根路径的 `/mobile`，不支持任意子路径挂载。填写地址不会自行建立转发。
4. 生成一次性配对码，手机打开二维码中的页面，填写设备名称并确认。配对码五分钟有效、只可用一次；手机凭据独立于桌面、最长三十天，可在电脑撤销。
5. 电脑保持 Mirally 运行并联网。凭据只放浏览器会话存储，关闭浏览器会话后可能需重新配对；配对码位于 URL 片段，连接后清除，不放永久主 token。

手机端口重启后保持，私人转发不需每次改目标。端口占用或手机配置损坏仅降级手机入口并保留原文件，不阻止普通桌面聊天。迁移机器需重新检查私人地址和配对，私有 home 不提交源码。

本轮验证为本机 HTTP 与真实浏览器链路；这台电脑尚未配置私人 HTTPS 转发，实体手机、移动网络及微信内置浏览器仍需实际验收。填写 URL 不等于 URL 已可达。

## 工作、会话和设置

默认工作优先，工作与会话均独立可达。手机可以核对来源、审阅/启动受信脚本、停止运行、读取日志和下载小型成果，也可新建、浏览、发送文字、重命名、固定、归档和恢复会话。历史分页读取同一 DSH transcript，不复制聊天库；标题筛选明确只覆盖已加载会话。

手机历史当前主要展示用户/助手正文，不自动外发思考、原始工具参数及历史媒体；输入为文字。桌面原材料、推理与工具展示保留。

设置提供工作/会话/继续上次首页、导航顺序与更多入口、工作排序、完成项显示、会话排序及恢复默认。用户默认与设备覆盖分层；当前页面和上次位置不强制同步。修改必须经过实际连接，浏览工作/会话不会改变微信下一条消息的目标。

通知按完成、异常、需要确认、渠道及单项工作设置，微信工作通知默认关闭。关闭通知不停止任务。手机与桌面消息页查看同一工作事件投影；微信通过原 outbox 投递，发送前复核来源/开关/安装身份，绑定改变不收养旧事件。消息页不是系统推送，发送窗口失效时保留可查询结果。

## 微信工作命令

原会话命令仍可用。工作入口包括：

| 命令 | 用途 |
| --- | --- |
| `/works` | 列表、实际状态及更新时间 |
| `/work 编号` | 查看工作、来源及最近运行 |
| `/work-new 目标` | 建立工作与主会话 |
| `/work-use 编号` | 明确在微信继续工作主会话 |
| `/work-status` | 所选/当前会话关联工作 |
| `/work-run 编号 {"script":"任务.py","arguments":[]}` | 准备脚本动作并展示影响 |
| `/work-review 完整审批编号` | 审阅电脑或手机准备的动作 |
| `/work-approve 确认码` | 批准已完整展示且未过期的具体动作并启动 |
| `/work-cancel 完整运行编号` | 停止真实受监督运行 |

“我的工作”“工作列表”等固定查询也可直接发送。动作有歧义时需明确目标，不将一句通用“确认”用于全部待批任务。确认码绑定安装身份、版本和具体审批；手机/微信可确认桌面准备的动作，启动凭据绑定实际批准入口。

`/stop` 只停止模型回复。微信媒体、QQ、任意终端、桌面接管及云 relay 不在本版；也没有微信原生自定义工作页面/按钮。电脑离线不能即时执行或通知。

## 数据与复现

数据库 schema 5 原地升级 1–4，保留原数据。`mobile-access.json` 保存手机 token/配对码哈希及呈现偏好，不复用会使会话来源换代的语义偏好。原 UI、动画、桌宠及历史回退数据不因本轮增加入口而迁移或删除。

```powershell
.\.venv\Scripts\python.exe tools/verify_framework_mobile_work.py
.\.venv\Scripts\python.exe tools/verify_framework_mobile_work.py --browser
node --test --test-concurrency=4 tests/test_*.mjs
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

工具只使用隔离 home、显式离线模型、回环连接与临时实际脚本，不登录或发送真实微信。GUI 顺序运行。另见[方案](mobile-work-control.md)与[验收记录](framework-v1-validation.md)。
