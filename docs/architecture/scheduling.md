# 日历、提醒与定时执行

更新：2026-10-31，Asia/Shanghai。状态：现行。相关实现：`mirally/framework/calendar.py`、`kernel/dsh/packages/mirally/mirally-product/src/calendar-tools.mjs`、`scheduled-actions.mjs`。

## 时区

在「设置 → 通用」确认产品时区，首次提供系统检测结果作为建议。可填写其他 IANA 时区，例如 `Asia/Shanghai`。该设置是解释自然语言日期、日历和定时动作的产品时区，不随系统时区变化自动更新。

事件保留实际时刻；日历展示按当前设置时区。周期动作在时区改变后按新时区的本地时间重新计算。不存在或重复的本地时间需要重新选择，不静默猜测。

## 日程

在会话中告诉 Mirally 会议时间和提醒要求，模型通过日历工具创建事件和提前提醒；成功后才能确认安排。桌面「日历」提供日程与提醒列表、编辑、取消及回到关联会话。

日程是产品 SQLite 中的持久事件，可关联原会话，也可独立存在。修改使用版本检查，冲突时提示重新查看，不覆盖他人更新。取消日程会阻止尚未投递的关联提醒。

## 提醒

明确提醒由产品 owner 持久保存，到期时原子写入消息页，并为启用的桌面和微信渠道分别生成投递。

- 桌面通过本机托盘通知；微信通过已有持久 outbox。渠道状态表示接口是否接受，不代表用户已读或系统一定展示。
- 支持一次、每天和每周重复。周期提醒取消时同时取消尚未投递的提醒。
- 电脑离线错过多次时，恢复后只补发一次；夏令时不存在的本地时间跳过，重复的时间只触发首次。
- 提醒不需要后台模型；“到时提醒”与“到时执行”是两件事。

明确提醒只有在持久约定创建成功、返回稳定 ID 和可执行时间后才显示“已建立”。模型口头答应不算。

## 定时执行

「到时执行」由产品定时 owner 复用 DSH 的时间规则，到期经过原会话命令准入和动作权限，在关联会话中执行。

- 支持一次、固定间隔、每日、每周和 cron；可暂停、恢复、修改和取消。
- 微信创建的任务在执行前检查原绑定；解绑会暂停派发。回合权限与桌面一致。
- 回复结束只表示该回合结束，不表示任务目标成功；完成后通过已启用的提醒渠道提示查看结果。
- 不可核实的派发结果停在未知状态，不自动重跑；异常重启不重放结果不明的执行。
- 电脑联网且 Mirally 保持运行是触发条件；退出、休眠和关机期间不保证即时提醒或执行。

## 投递与设置

桌面和微信渠道的提醒开关在通用设置中。账号解绑、来源撤回或事件取消会阻止尚未投递的内容；发送结果未知不盲目重发。

## 当前边界

- 周期日历事件、外部日历同步和邀请多人暂不支持；日历扩展可按领域接口后续接入。
- 微信不能创建定时执行任务；可在桌面会话中创建，或在微信中管理已有日程与提醒。
- 真实 Windows 通知展示、微信平台长期主动投递和夏令时边界仍需按实际环境验证。
