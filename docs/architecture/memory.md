# 记忆

更新：2026-10-31，Asia/Shanghai。状态：现行。相关实现：`mirally/core/memory/`、`mirally/runtime/memory/`、`mirally/framework_workers.py`。

持久记忆独立于聊天历史：模型 Session 可以更换或结束，记忆仍由 MemoryStore 保存，并可从活动数据按来源、预算和维护规则更新。记忆不是用户画像，也不是对全部原始活动的复制。

## 存储与来源

| 数据 | 位置 |
| --- | --- |
| 持久记忆 | `<home>/memory/memory.sqlite3` |
| 活动投影 | `<home>/memory/activity-projection.sqlite3`（可重建） |
| 原始活动 | 由 Activity owner 保存在其数据库中 |

每条记忆保留来源引用、观察时间、状态（active / candidate / retracted / superseded）、冲突键和必要版本。来源被撤回时写入墓碑；后续查询返回不可用状态，不重新生成内容。投影重建不会重置持久记忆。

## 默认行为

| 能力 | 默认 | 说明 |
| --- | --- | --- |
| 持久记忆 | 开 | 本地规则维护可运行 |
| 本地活动整理 | 开 | 每两秒处理最多 200 条新观察，按五分钟窗口聚合 |
| 模型语义整理 | 关 | 需要开启后台模型并选择连接 |
| 后台摘要/主动联系 | 关 | 与记忆语义预算相互独立 |

模型语义整理的默认预算为每小时 4 次、每日 24,000 tokens、单次最多 1,500 输出 tokens，可在设置中调整。后台请求提交前复核当前授权、来源版本和 owner；配置或来源撤销后，迟到结果不能写入。

## 维护流程

```text
Activity Observation Store
  → 只读增量投影
  → 本地规则窗口（5 分钟 + 60 秒迟到宽限）
  → 可选模型语义整理（经同一模型桥）
  → MemoryStore
  → 只读召回 / Context / Memory 页面
```

- 工作快照 24 小时后过期；情景摘要保持持久。
- 本地整理不调用模型，失败不阻塞采集；模型整理失败保留作业状态，不把失败写成事实。
- 撤回 Activity、Memory 或观察来源时，后台语义整理保守暂停并显示 `source_blocked`；重新授权后恢复。偏好撤回不阻断不使用偏好的整理。
- 原始资料清理需要稳定窗口的模型总结和匹配的持久回执；本地规则摘要、失败或预算等待不授权删除。默认未开启模型整理时，原始资料可能持续占用配额，需要用户明确处理。

## 召回与查看

- `MemoryReader` 提供受限的搜索、读取和上下文组合；查询只读，不启动采集或维护。
- Context 按当前问题选择有限记忆，返回来源、时间、预算和缺口；预算按 UTF-8 字节保守估算，不能把预算内结果当成完整历史。
- 「记忆」页面支持按来源、类型、日期和关键词筛选，可选择包含待审核记忆，查看正文分页、观测时间和原始证据状态；查看候选不会自动晋升为长期事实。
- 可显式创建或纠正记忆：新内容通过 `memory.correct` 写入，已有记忆使用明确 ID；相同创建请求只读重放，不同内容冲突。纠正保留替代关系，不静默覆盖原记录。
- 微信助理可通过记忆工具检索或在明确要求时读取，不把摘要当作实时状态。

## 明确边界

- 记忆保存的是值得保留的经历和可修正主张，不是全部聊天、原始截图或任务运行状态。
- “不要再主动提”修改联系策略；“停止使用这条记录”还需要撤回来源、阻止派生继续使用，并处理已召回的原生上下文。删除 Memory 记录不等于擦除已经发送给模型服务的数据或历史文件。
- 当前使用 SQLite/FTS 的本地检索，没有默认向量数据库或跨设备同步；中文、时间、跨会话和纠正效果仍需按实际数据评测。
- 语义整理只自动补处理最近一小时，更早积压没有全历史自动补处理；限制与处置见[活动数据层](activity.md)。
