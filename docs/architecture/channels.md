# 消息渠道：微信、语音与手机

更新：2026-10-31，Asia/Shanghai。状态：现行。相关实现：`mirally/framework/channels.py`、`kernel/dsh/packages/mirally/mirally-product/src/channels/`、`src/mobile.mjs`、`speech-service.mjs`。

微信是默认的手机入口，不需要自建云服务器或公网端口。手机网页是可选扩展，与微信共用同一产品状态和 DSH 会话。两种渠道都不复制聊天历史，也不另建模型路由。

## 微信连接

在「设置 → 消息渠道 → 微信」点击连接，用本人手机微信扫码；若平台要求验证码，在当前页面输入。扫码后仍需在本机选择已有会话或新建会话并确认绑定。

- 二维码在本机编码，不依赖远程图片或电脑微信窗口；连接由桌面主动 HTTPS 长轮询，不开放本机入站端口。
- 微信授权页可能显示 OpenClaw。当前公开协议只提供固定通道入口与观测用 `bot_agent`，没有可用的授权页显示名参数；Mirally 请求的观测标识是 `Mirally/0.1.0`，不改变平台授权文案。这并不表示产品重新运行 OpenClaw Gateway。
- 暂停连接保留绑定与历史；重新连接恢复收消息。解绑撤销旧身份、清除本机微信凭据和待发队列，保留 Mirally 会话。
- Windows token 与会话发送令牌使用当前用户 DPAPI 保护，不发给浏览器。复制 home 到另一 Windows 用户或机器后无法解密时，只需重新登录微信，不阻断普通聊天。

## 助理与会话模式

新绑定默认使用「助理」。设置页可在「助理」与「直接会话」之间选择；微信发送“助理”或 `/assistant on` 进入助理，发送“会话模式”或 `/assistant off` 返回之前选择的直接会话。

- **助理**有自己的对话上下文，可查找会话、查看会话状态与所属后台作业，并在用户明确要求时向目标原会话发出委托、等待其真实回复。目标不明确时先询问，不猜测。
- **直接会话**把普通文字送入所选会话，保留该会话的上下文和微信来源。
- 普通自然语言进入当前模式的会话，不经过额外分类模型。切换模式不支持中断正在执行的微信回合。
- 进入助理后，提示会说明发送“会话模式”可回到哪个直接会话；`/status` 同时显示当前模式。

## 可用命令

| 命令 | 作用 |
| --- | --- |
| `/help`、菜单、帮助 | 显示微信菜单 |
| `/sessions`、会话 | 列出会话；使用最近一次完整送达的列表编号 |
| `/use 1`、切换 1 | 切换到编号对应的会话；同名或目标不明确时拒绝猜测 |
| `/new [名称]`、新对话 | 新建会话 |
| `/status`、当前会话 | 显示当前会话、当前模式（助理/直接会话）与运行状态 |
| `/history [游标]` | 查看当前会话正文历史 |
| `/stop`、停止回复 | 停止所选会话的当前回复 |
| `/assistant on` / `/assistant off` | 切换助理/直接会话 |
| `/answer` | 回答桌面发起并投递到微信的结构化问题 |
| 日程、今日日程、明日日程 | 查看日程；再用“查看日程 1”“进入日程 1”选择 |

每个含微信输入的活动会话只接受一个命令；忙时说明当前会话还在回复上一条消息，并给出“停止回复”这一入口，防止排队消息改变当前工具权限。列表编号绑定当前绑定和最近一次完整送达的列表，不跨列表复用；失效时统一称“编号”并指向重新查看的入口。

## 媒体与语音

微信支持文字、语音、图片、文件和视频：

- 平台提供语音转写时直接使用；否则下载并解码，再由配置的语音服务识别。
- 图片和文件进入当前会话的材料处理；模型能否理解取决于视觉能力和文件提取结果。视频作为文件保存，不代表已解析。
- 单项媒体上限 8 MiB，每条最多 12 项；附件回执带项数，下载、解码或识别失败时回显本渠道给出的具体原因（大小、密钥、编码、未配置识别），其他错误只说明失败，不提交部分文本，也不回显协议或凭据信息。
- 用户明确要求且微信可操作时，可把当前会话已保存的成果作为文件或图片发回微信；发送有持久回执，未确认的发送不自动重发。
- 语音回复尚未接入。账号与客户端对媒体的实际表现仍需实机确认。

桌面对话输入区可点击麦克风开始录音，再点击停止；识别结果追加到草稿，由用户检查和发送。切换会话或离开输入区会取消录音或识别，不是常驻监听。

语音服务在「设置 → 通用 → 语音识别」单独配置：填写兼容 OpenAI 音频转写接口的服务地址、模型和密钥，或选择本地 Whisper。本地识别需先安装依赖并准备兼容 faster-whisper 的模型目录，不会自动下载：

```powershell
.\.venv\Scripts\python.exe -m pip install faster-whisper
```

录音在识别期间写入系统临时目录；正常完成、取消和退出会尽力删除，系统和进程异常终止时无法保证清理。语音密钥使用当前用户 DPAPI 保护，迁到其他用户或机器后需重新填写。

## 权限与投递

- 微信与桌面共用同一动作审批策略；账号绑定、会话归属和来源仍分别校验。当前不再提供渠道级“远程控制/自动批准”开关，避免出现与桌面不一致的第二套权限。
- 模型与工具权限随实际接入能力变化，不由静态渠道白名单决定。网页搜索等能力仍受各自的产品设置和供应商支持约束。
- 仅明确关联的助手正文经持久队列回发，过滤思考和原始工具信息；长回复超过 14000 字时标出截断位置，并按 `（1/3）` 中文前缀顺序分段，部分失败后停止余下段落。
- 平台接受、手机实收和用户已读分开记录；未知发送不自动重发。重启不重放旧模型输入，无法核实的历史积压保留状态。
- 电脑离线、睡眠、退出或断网时无法接收微信指令或即时发送通知；关闭到托盘可以继续收发。

## 手机网页

「设置 → 消息渠道」可选启用手机网页。页面 `/mobile` 是独立 Vite 入口，复用主题，通过独立受限服务访问同一产品状态，不加载桌面管理壳或主凭据。

- 使用一次性配对、可撤销设备身份和有限 RPC；配对、撤销、私人 HTTPS 转发与显示偏好都在桌面设置中管理。
- 异地访问需要自行准备私人 HTTPS 转发或网络；把本机回环地址发给手机不算完成远程访问。
- 手机页面可查看会话、消息和偏好，默认显示会话；切换页面不隐式改变下一条微信消息的目标。
- 手机网页拥有独立且有限的操作范围，不等同于完整桌面控制面；取消配对会撤销该设备访问。

## 当前未覆盖

- QQ 机器人、企业微信、公众号等渠道未接入；公共协议存在不代表账号已获准使用。
- 微信语音回复、完整媒体兼容、跨设备推送和长期主动投递未验收。
- 实时进入微信聊天界面等事件不可用，不能据此可靠提示“用户已打开聊天”。
- 平台授权名称、账号资格和客户端展示由腾讯控制，不能由 Mirally 单方面修改。

验证命令与未覆盖范围见[验证](../reference/validation.md)。
