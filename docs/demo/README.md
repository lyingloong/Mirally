# 办公协作演示与验收

用两份合成材料演示“托付材料 → 运行中补充 → 清楚交接”。材料中的人名、项目和数据均为虚构，可用于内部教学或日常办公展示。此页提供复现步骤、核对标准，以及机器侧已完成和仍需人工确认的范围。

## 准备与启动

使用已配置模型的项目环境，在项目根目录执行：

```powershell
.\run-openclaw.ps1 mirally
```

等待进入工作台，准备[会议纪要](meeting-notes.md)和[项目背景](project-background.md)。新建一个普通会话，避免之前的文件或回答影响展示。主入口的「侧边伙伴」与旧 `companion` 实验 Tk 客户端不同。

## 一次完整演示

1. 在尚未发送消息的原生新会话页面直接点击「工作」，选择「整理会议」，不必先发问候或占位消息。页面共十种工作起点，还包括汇报、比较、读材料、打磨文稿、网页研究、看图、一起看页面、从想法写起和其他工作。选择只准备任务，原来的草稿与附件交接到会话，不自动提交；原生侧栏仍可使用。
2. 将两份材料拖入工作页面的材料区，确认附件名称与读取状态，也可以点击添加材料使用文件选择器。材料与当前对话共用，不要只把文件名写进要求。
3. 在工作要求区填写以下内容，选择「可编辑文档」，核对后点击「开始这项工作」。成功提交后会显示原生对话，原来的文字草稿仍保留，已发送材料从附件准备区清理。输出目录可改为你自己的空目录：

   ```text
   请同时阅读这两份附件，整理项目进展和行动清单。
   将确定内容与材料冲突分开，不自行决定日期、预算或负责人。
   先完成能够确定的部分，分歧标为待确认，不必等待确认才写初稿。
   请在 D:\Projects\openassist\output\mirally-office-demo 中实际保存
   progress-report.md 和 action-items.md，使用中文。
   清单包含事项、负责人、日期、状态和材料来源。
   只生成内部草稿，不发送给别人、不预约、不采购。
   ```

4. 点击「侧边伙伴」，在其他应用中继续正常操作，观察真实进展。任务仍在运行时发送：

   ```text
   换成给老师汇报版：措辞克制，区分已完成、观察到的问题和下一步。
   说明反馈仅来自材料中的 5 名合成体验者，不能作为产品效果结论。
   两份材料的冲突继续保留为待确认，并标明来源。
   ```

   补充走原生运行中调整机制。若任务已完成，这条消息属于后续修改，不能当作“中途补充已验证”；可在另一次运行中再测。
5. 完成后查看交接。「已完成、待确认、下一步」来自实际回复；普通回答没有对应标题时展示回复回顾。点击「查看回复」检查依据，再点击「查看成果」进入原生 Files 面板，打开两个文件。
6. 用文件管理器核对输出目录确实存在两个文件，打开检查内容。回答中声称“已保存”或显示路径都不够。伙伴里的文件入口属于整个会话，不能仅凭出现在列表中就认定是本轮新产物。
7. 点击「接着推进」，检查出现的是可编辑草稿，没有自动发送。可以要求把其中一个待办细化，继续同一会话。
8. 有交接待确认事项时，点击「补充确认」，填写自己的决定再发送；已有草稿会保留。它准备普通对话，不代替工具权限审批，也不自动批准安排。

## 应核对的结果

| 核对项 | 预期 |
| --- | --- |

| 展示日期冲突 | A 为 2026-10-12，B 为 2026-10-14；两者并列待确认 |

## 历史机器侧结果（旧办公准备流程）

以下记录来自此前的办公起步与浮窗流程，可作为后台执行、交接与补充的依据，不能代替本轮工作页面及新入口的用户验收。

2026-10-04 已在独立合成会话中通过原生界面读取两份附件，实际生成并读回两份 Markdown 文档，保留三处冲突与来源。后续修改成功采用给老师汇报的标题和合成小样本说明。结构化交接、固定入口、旧办公准备流程与确认草稿保留完成真实窗口复验；6 项 Node 测试、13 项相关 Python 测试通过。证据在本机 `output/openclaw-native-verification/office/`，运行状态和配置由原生管理。

这次办公请求首个工具响应约 160 秒，首轮最终回复约 302 秒；最初的 150 秒等待超时，随后文件生成成功。补充消息的 `message.created` 时间在初始请求之后约 5.68 秒，后续较晚的会话记录时间代表消息被消费或写入记录，不能据此认定补充是在首轮结束后才发送。不过这次没有记录运行中补充的接纳过程，仍不能单凭创建时间和最终文件证明它已进入活跃任务。验收要区分创建、接收、记录和最终采用，不能仅看界面工作动效。耗时分析与配置修正见[响应耗时说明](../response-latency.md)。

随后单独完成约 48 秒的运行中补充验收：后台工具确实仍在等待、原生 `inFlightRun` 尚未结束时，由实际浮窗提交 `steer`；记录发送时刻与接收确认，最终文件采用补充指定的新标记。9 项检查通过，证据在本机 `output/openclaw-native-verification/office-steer/`；这次专门验收是运行中调整已通过的依据。明天仍需在自然办公任务里观察补充的实际体感与响应时间。

耗时修正后，另一次实际浮窗流程的 17 项检查通过：两份附件添加本次独立标记，核对真实文件、补充要求、分歧、交接与固定入口。从发送到原生空闲约 119 秒；本次补充在模型尚未启动时到达，按原生语义排为后续回合。8 项 Node 测试和上述 13 项 Python 测试通过。证据在 `output/openclaw-native-verification/latency/office-clear/`；单次速度和剩余冷准备、模型生成成本见[响应耗时说明](../response-latency.md)。

## 本轮界面与截图交接的机器侧结果

丰富工作页面实际 GUI 27 项检查通过，覆盖十种起点、四种输出、按工作类型变化的准备、网页链接、图片预览、会话隔离及小窗口/最大化布局。选卡进入独立准备布局，「换个起点」返回卡片列表。原生未发送新会话入口重新通过 10 项检查，草稿与附件保留，不发送占位消息；22 项 Python 与 18 项 JavaScript 自动检查通过。证据在本机 `output/openclaw-native-verification/rich-work/verification.json` 与 `new-page/verification.json`。

合成窗口的截图采集→原生附件→工作台/伙伴双预览链路通过 11 项检查：480×320 尺寸、像素和标题匹配，未发送无工作回合，前台焦点不变；证据在 `output/openclaw-native-verification/context-handoff/verification.json`。真实不同应用截图兼容性仍需你验收。

模型识图另经实际界面验证：当前 Qwen3.8-flash 补齐原生图片能力声明后，单张自绘图片中的 73、红色三角形、蓝色正方形识别正确，6 项检查通过，Gateway 进程不变。证据在 `output/openclaw-native-verification/vision/verification.json`；复杂图片与音视频不是这次验证覆盖的内容。

## 当前人工待核对

- **本轮界面修复**：刚启动、不悬停就进入侧边伙伴，检查是否仍有右侧白块；新建、打开与切换会话，检查入口是否还在。
- **新会话与工作页面**：原生未发送的新会话可直接进入工作/伙伴，不先发占位文字；该路径有 10 项机器侧检查。选择十种起点、拖入材料、编辑内容/受众/侧重并切换四种交付方式；返回对话核对原有草稿。成功提交后检查附件与准备表单清理，未接纳时要求和材料可找回。
- **伙伴形态与拖入**：侧栏、图标、伙伴三形态都能选择；用「⠿」手柄或 Alt 拖动移动位置，收起的图标/伙伴可直接拖。网页链接、文字、图片、文件拖入仅准备，不自动执行。白底修复已有侧栏、图标、伙伴、展开面板四形态的真实桌面像素/外部点击检查通过，且前台焦点不变、恢复窗口样式与背景正确；本机证据在 `output/openclaw-native-verification/desktop-clip/result-*.json`，用户首次进入与自然操作仍待复测。
- **一起看页面**：从独立「◎」截图手柄明确拖向目标窗口，与移动伙伴不同；它带回一次截图供预览、填写要求、再提交。可见区域采集可能包含遮挡。截图不是实时自动控制许可，不自动读取整页 HTML 或 URL，后台读网页需提供链接。合成窗口交接与当前模型基础识图已分别验证，真实不同窗口兼容性仍待核对，未发送源截图不额外存盘。
- **音视频材料**：会议卡片允许带入录音或视频，但当前转写能力尚无已配置保证；核对助手是否明确告知无法解析，不把未读取内容说成已经听到。
- **桌面体感**：正常使用鼠标和其他应用时是否干扰；靠近、离开、输入、最小化和恢复是否连贯，长交接时固定的回复与文件入口是否仍容易找到。
- **常见格式**：另外测试自己的非敏感 PDF、DOCX、XLSX 等材料，核对解析内容和文件交付；这两份 Markdown 不能代表所有格式已支持。
- **真实审批**：遇到原生权限审批时，检查完整工作台能否正确处理并返回伙伴。文档中的“待确认”文字不等于工具权限审批；不要为展示制造不必要的外部操作。
- **跨会话**：启动另一会话任务，切回当前会话，检查伙伴的后台工作或需查看入口和点击切换。当前只展示原生已加载会话的状态，不承诺覆盖未加载的全部任务。
- **补充时序与耗时**：在明确的持续工具操作期间补充，核对原生运行是否仍活跃，以及最终文件是否采用要求；进一步区分原生执行、中转响应和模型耗时。已通过原生模型元数据适配修正 thinking `off` 的映射，继续核对实际响应与质量。
- **恢复**：刷新或重连后核对同一会话和草稿，不重复发送任务；记录问题时区分模型回答、附件解析与界面显示。

当前工作页面替换旧办公起步弹窗，仍复用原生附件、发送、会话和实际回复，没有新增运行依赖、持久存储、模型服务或身份规则。更完整的逐项检查见[功能与体验验收清单](../mirally-feature-checklist.md)，窗口边界见[桌面套壳说明](../openclaw-desktop-shell.md)。
