# 旧实现迁移收尾与维护切换

更新于 2026-10-26，Asia/Shanghai。依据 PN-0027：迁移完成后，新框架是唯一继续开发的产品实现。旧分支 `feat/mirally-openclaw-desktop` / `2eeb778a` 保留历史与回退，不再承担新增功能、双向同步或另一套产品验收。

范围澄清（2026-10-27）：本文的“收尾”只指下表中已列出的阶段性迁移与维护切换，不表示新框架已恢复旧版的全部实际行动能力。后续已增加逐次审批的命令、进程、独立浏览器和桌面观察；当前范围和限制以[框架第一版](framework-v1.md)与 PN-0051 为准，不能据此推断旧版能力已全部恢复。

## 本次迁移范围

| 项目 | 新框架的实现与验收方式 |
| --- | --- |
| 会话组织 | Conversation owner 保存标题、固定、归档和元数据版本；原侧栏和标题菜单接入。并发版本冲突不能覆盖他人的更新；活跃工作不能归档，归档后拒绝新输入，恢复后可继续。归档和撤销只改元数据，不改 DSH Session 身份 |
| 历史材料与工具 | 从 DSH 原生事件和所有会话代次派生图片、文件、工具参数与结果。历史和实时回执共享稳定身份，刷新及冷启不重复工具卡；附件接口只授权该逻辑会话真实引用的内容，不接收任意本机路径 |
| 旧会话档案 | 显式迁移复制原文件并核对指纹，设置 → 关于提供只读分页查看。已有的索引可明确复制到新目录；原目录随后移走也可读取。保留来源，不转换或伪装成 DSH 会话，不自动发送旧内容 |
| 多模型 | 默认连接兼容原配置，命名连接独立保存凭据，对话与后台分别选路。探测指向明确连接，连接改动使旧请求失效；已被用途或开启的网页能力引用的连接不能删除。密钥不回显，不跨服务来源继承 |
| 网页与文件 | 产品原生基础工具包接入唯一 DSH 工具管线。工作区读取与明确授权目录的只读列表、搜索、正文提取；工作区文字写入需全局开关和本次工作的保存许可，覆盖已有文件需匹配最近读取的指纹。网页搜索与正文读取单独开启，首个内置服务为 DeepSeek 官方接口；其他服务可经 MCP/插件接入 |

原开屏、主题、布局、工作准备、材料草稿、三段交接、成果查看、伙伴三形态、海獭/飞狐、窗口裁剪/菜单/托盘和 Activity/Memory 管理继续复用。对应关系见[体验迁移对照](framework-experience-migration.md)；结果与未覆盖环境见[验收记录](framework-v1-validation.md)。

## 唯一维护边界

- 新问题、新能力和扩展在 Mirally 产品接口与同仓 DSH 内核内实现，不再增加 OpenClaw Gateway 依赖，也不要求旧路线同步功能。
- `frontend/control-ui/` 是 Mirally 自有维护的固定来源组件。保留原视觉与许可，已有 `upstream-files.json` / `local-changes.json` 继续说明来源和维护接缝；普通构建和产品运行不需要旧发行包。
- 旧 `--openclaw` 入口、维护适配和既有私有数据暂存为显式回退参考，不自动启动、不自动消费配置、不双写。这里的冻结不表示立即删除用户旧数据或 Git 历史。
- 共享的 Activity/Memory、Windows 窗口、伙伴资源仍属于新产品；不能因为它们先前被旧宿主使用就当作废弃代码。未来删除旧适配前，按运行依赖与持久数据归属核对。
- UFO 继续不接入。后续 Windows 执行能力围绕 Mirally 接口独立设计，不恢复旧主链。

## 数据交接

新数据保存在新 home 中。迁移要求显式来源、空目标、停止旧 owner，预览和应用复核指纹、SQLite WAL 与复制结果；源文件不会被修改或删除。旧记录归档保存在 `framework/legacy-sessions/`，索引保留来源指纹和相对归档地址，移动整个 home 后仍可查看。超限或格式异常的旧记录明确报错，不能悄悄漏掉后宣布迁移成功。

新会话继续以 DSH 为唯一 transcript owner。旧档案只读、提醒与记忆仍由各自领域 owner 管理；UI 不保存第二份聊天事实。无需导入的历史不强制导入，用户选择保留原目录即可。

## 有意保留的产品范围

迁移追求可用体验与职责完整，不将旧宿主的每项管理能力直接带入产品：

- 会话删除、分叉、无痕模式、宿主渠道与账号管理仍不提供；菜单与接口不得假装支持。
- 当时的基础文件能力是有界读取、文字搜索和工作区文字写入；Office/PDF 提取仍遵循[材料限制](framework-experience-migration.md#材料与成果)。后续命令工具拥有当前用户权限，并非操作系统沙箱。
- 当时的网页研究工具使用独立的服务接口，默认关闭；后续独立浏览器支持逐次确认的页面读取和操作，不接管用户已有浏览器登录状态。
- 完整语音、跨设备联系、成熟长期陪伴与自主 Windows 操作属于后续产品迭代，不再记成“等待迁回旧实现”的缺口。

这些边界可随新产品需求改变，不要求回头维护旧路线。长期方向见[产品框架](personal-agent-framework.md)和[扩展接口](framework-extensions.md)。

内置网页服务按 DeepSeek 官方 [Search](https://api-docs.deepseek.com/api/search/) 与 [Fetch](https://api-docs.deepseek.com/api/fetch/) 接口实现，2026-10-26 用保存连接的隔离凭据副本分别实测一次公开查询和文档抓取。未发送个人记录；这证明首个适配器可用，不代表其他供应商或所有网页都可访问。
