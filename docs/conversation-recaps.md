# 会话摘要与自动命名

会话摘要是供人和微信助理浏览的历史投影。原始对话与内核压缩上下文仍是继续对话的依据；摘要不代表实时任务状态，也不能代替工作状态或命令结果。Codex 等系统使用上下文压缩延续长对话，但 [OpenAI 的压缩对象](https://developers.openai.com/api/docs/guides/compaction) 不以人类可读为目的，因此不能直接作为会话摘要。

当前实现按会话当前代的最近 30 条文本消息生成简短摘要和标题；无法完整读取历史时不生成，旧代及附件不会被隐式传给摘要模型。摘要记录其代与命令版本；更新期间有新消息、会话冻结、归档或相关来源撤权时拒绝写入。生成后的新消息会将摘要标记为过期。自动标题先使用首条消息作为无模型的后备，首次成功生成时改为模型标题；用户手动命名始终优先，已生成的标题不会每轮变化。

用户主动生成时使用设置中的后台模型，可能产生模型调用费用。自动生成仅在后台能力开启时进行，最多每会话每十分钟一次、全局每天十二次；该次数上限独立于记忆语义整理的预算，模型调用分别计费。摘要失败不会影响消息发送。桌面可调用 `POST /api/sessions/{id}/recap`，返回操作状态；`GET /api/sessions` 的 `recap` 返回正文、生成时间及是否过期，未生成时为 null。微信助理可通过摘要工具读取或在用户明确要求时刷新。无后台模型、来源撤销、历史缺失或模型调用失败不会伪装为成功。

摘要只取最近消息，长对话早期信息可能缺失；不从压缩记录推断完整历史，不做自动定期重建或跨代继承。未来可考虑增量合并、摘要证据定位、自定义生成频率及关闭摘要，但应继续保留来源授权、费用预算和并发版本检查。
