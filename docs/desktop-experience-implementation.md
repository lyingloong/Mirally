# 桌面体验实现与验证

本文描述迁移前 UFO 入口的实现与验证边界，使用 `.\run.ps1 --ufo`。当前默认入口已改为[完整 OpenClaw 官方界面的桌面套壳](openclaw-desktop-shell.md)，以下浮窗、主题、输入协调及截图机制不套用到新核心。安装与日常操作见 [项目 README](../README.md)，规划中的能力见 [体验目标](frontend-experience-goals.md)，全部文档见 [文档导航](README.md)。

**原生执行接入范围（2026-10-04 核对）：** 默认 UFO 原生适配器已经接入统一任务协议、会话上下文、运行中补充、动作前门禁、结构化进度/结果和截图/控件隔离。验证覆盖隔离进程与离线模型替身；真实桌面仍需在专用测试窗口上运行 `tools/verify_desktop_isolation.py`，该脚本不连接模型，也不操作其他应用。暂停、停止和第三方工具超时都是协作式边界，正在执行的不可中断调用必须先返回。具体调用关系见 [OpenAssist 与 UFO 接入详解](ufo-integration.md#当前接入范围与限制)。

Mirally 当前默认采用「晴空蓝」：银白背景、深灰文字、少量天蓝强调。正式图标采用 [相伴 M](design-concepts/mirally/companion-m/README.md)：由用户提供的蓝青双人流线图精修为透明底生产资源，替代此前合翼 A，原始 [天蓝界面探索](design-concepts/2026-10-03/sky-blue/README.md) 保留作为设计记录。明亮天蓝用于状态指示，按钮与小字号强调使用更深的蓝以保证可读性；原有主题仍可选。现有 Python 3.10、根目录 `.venv`、`run.ps1` 和模型配置均沿用，Python 包和配置目录保持 `openassist`。

## 品牌、开屏与自适应布局

窗口标题、任务栏图标、主界面与浮窗使用同一相伴 M 标记和 Mirally 名称。正式母版为 `assets/mirally.svg`，`tools/render_brand_vector.py` 以三倍分辨率渲染后统一导出各尺寸。`branding.py` 从应用自身的 `assets/` 加载透明 PNG 和多尺寸 ICO，不依赖工作目录或设计输出目录，也不需要运行时 SVG 渲染器；晴空蓝与石墨主题均使用透明背景素材。

开屏在主窗口内部播放约 2.8 秒：天蓝柔光逐渐扩散，三条光带环绕现用图标，少量光点缓慢移动，字标与伙伴文案分段浮现；最后约 0.6 秒向上收起进入工作台。首个点击或按键可以跳过，首个输入字符仍保留；底部有跳过提示，启用「减少动态效果」时直接进入主界面。计时使用实际经过时间与 Tk 回调，不阻塞输入、不建立额外弹窗，关闭时清理回调。图标和 Canvas 元素只创建一次，逐帧更新坐标与颜色，不逐帧加载图片。`tools/preview_startup.py` 可生成本机界面的 56 帧分镜与 GIF（位于忽略上传的 `output/mirally-startup/`）；这是定时取样的设计预览，不是显示器帧率测量。

工作区宽度达到 980 逻辑像素时增加会话侧栏，直接点击历史会话切换，当前会话使用浅蓝填充与蓝色标记。窄窗口通过顶部与「浮窗、记忆、设置」并列的「历史」按钮打开同一套列表，列表顶部提供新建；所有会话下拉框已移除。「记忆」专门查看当前上下文与清空。列表支持滚轮、方向键和 Enter，选择后返回对话。运行时禁用会话切换和新建，避免混用上下文。主区域随剩余空间伸展，对话字号、内边距和输入区同步适配。小窗口追问/确认时收起重复的介绍文案，为补充回执和确认按钮保留空间。歌词式工作状态采用有上限的居中内容列，避免全屏时文字仍挤在小窗口大小的区域内。空闲或任务结束后隐藏桌面暂停/接管控件，为对话和小窗口输入留出空间。

设置、记忆、记录按钮使用独立的选中状态：浅色填充、蓝色文字和完整圆角边框。按钮资源以四倍分辨率抗锯齿生成，边框为 1.25 逻辑像素，焦点环为 1.75 逻辑像素，并预留间隔；选中、悬停、按下与键盘焦点可以组合。卡片内按钮使用匹配表面背景的样式，避免圆角外出现矩形底片，各状态不改变按钮尺寸。

顶部「收回」按钮现已更名为「浮窗」，用途不变。设置页改用带真实背景色、强调色与文字色预览的主题卡片；当前主题显示勾选和完整描边。窄窗口两列，设置内容宽度达到 720 逻辑像素时四列。「减少动态效果」「窗口保持置顶」使用统一圆角开关行。主题与开关支持 Tab、空格、Enter 和鼠标；内容超出小窗口时提供滚轮与滚动条，键盘聚焦的选项会滚动到可见区域。选项仍保存在原有本地偏好文件。

## 工作台与侧边形态

- `run.ps1`：对话助手与 UFO 原生 HostAgent/AppAgent 桌面执行器。
- `run.ps1 --demo`：离线演示，不调用模型、不操作桌面，会话默认仅存在内存中。
- `run.ps1 --legacy`：旧版界面与 UFO 原生多智能体适配器；没有新版会话工作台的完整保证。

启动时显示可滚动的对话。空闲时即可点击「浮窗」手动进入浮窗；进入桌面执行流程时自动用约 320ms 过渡收至当前显示器工作区右侧。等待回答/确认或正在停止时，不允许手动收回问题窗口。紧凑卡片约 272×120 逻辑像素，展示动作、步骤和状态；物理鼠标靠近后展开约 370×340 的补充面板。仅展开查看进度不会取得输入控制权，工作与活动指示继续。进入输入区、悬停最小化按钮或按展开输入快捷键时才请求输入控制。展开和收起保持同一侧边锚点，窗口始终不透明。减少动态效果设置会跳过过渡与活动节奏。

展开面板提供输入、最近回执、暂停、停止和打开会话。发送后收回；展开稳定后，鼠标离开面板及其边缘容差区即在下一次界面轮询时开始收回动画，靠近紧凑浮窗也无需悬停等待（轮询间隔约 40ms）。取消原有悬停、离开和收起后的定时冷却，保留约 320ms 的形变动画；动画期间不重复触发。手动收起后若鼠标仍在紧凑浮窗内，需移出再靠近才重新展开，避免立即弹回。输入框有未发送草稿时不自动收回。未发送草稿会保留，已发送文本不再被迁移回草稿。追问与敏感确认打开完整工作台以显示完整内容，回答或确认后随执行器恢复工作返回浮窗。由浮窗临时打开的追问保留返回状态，即使关闭自动收边也能正确返回。手动收边仍不能绕过待回答的问题。最大化、全屏和最小尺寸在收边前保存，重新打开完整工作台时恢复。主题共用排版、字体与交互路径。

从浮窗提交新请求后，理解意图期间仍保持浮窗。若随后决定执行桌面任务，直接在浮窗进入工作，不先展开主窗口；若返回普通聊天回复，则在完成后打开工作台呈现完整回答。不能根据暂时的 `conversation` 模式提前判断最终是聊天还是执行。

展开浮窗右上角的「−」用于最小化到任务栏，不再作为收缩按钮。移开鼠标仍按原规则收缩。最小化保留未发送草稿；桌面工作期间会先释放编辑占用，让任务继续。可从任务栏恢复，或用展开补充快捷键重新打开；最小化期间不响应悬停，截图流程不会意外恢复窗口。收到需要用户回应的追问或确认时，仍可恢复工作台展示问题。

减号由纯 Canvas 文字改为真实按钮，提供圆角悬停底色、按下态、手形光标与键盘焦点。工作态输入穿透时，使用已有物理指针轮询更新悬停反馈；停留在减号的实际按钮区域约 150ms 后请求输入让出，沿用补充输入的门禁，不因查看其他进度区域而暂停操作。最小化时释放输入占用。

使用展开输入快捷键时，即使鼠标还在浮窗外也保留输入面板，避免即时收缩打断键盘输入。发送、Esc 或最小化结束此状态；鼠标进入面板后恢复正常的移出收缩规则，未发送草稿仍受保护。

Tk 切换 `overrideredirect` 会重建外层 HWND，并设置 `WS_EX_TOOLWINDOW`。因此不能只在最小化前设置样式：进入浮窗及更新输入穿透样式后，均确保 `WS_EX_APPWINDOW`、清除工具窗口标志，并通过 Windows `ITaskbarList.AddTab` 为新 HWND 登记任务栏入口。最小化前再次登记；登记失败时不执行隐藏操作。刷新样式不通过隐藏/显示窗口实现，避免破坏截图隔离。验证必须找到真实任务栏按钮并通过该按钮恢复，不能只以 `IsIconic` 或样式位判定成功。

最大化/全屏切换时，外层原生窗口新露出的区域使用与主题一致的背景画刷，并关闭本窗口的系统过渡；工作台在尺寸变化事件内立即更新宽窄布局，避免额外等待一次空闲绘制。画刷随主题更换，并在关闭时恢复原值、释放资源。此设置仅影响本进程的 Tk 顶层窗口类，不改变桌面主题或系统动画偏好。

冷启动另行修复：隐藏的 Tk 根窗口在初始阶段只暴露 `TkChild`，此前背景和 DWM 初始化误作用于子窗口。现在先完成空闲几何布局，确保创建真实 `TkTopLevel`，再设置画刷与过渡；根窗口映射时再次同步，以覆盖浮窗切换导致的 HWND 重建。相同主题复用画刷，避免映射时重复创建 GDI 资源。验证必须先测从未进入浮窗的第一次最大化，再测浮窗往返后的路径。

恢复工作通过 `resume_working()` 完成形态交接，再启用工作态的输入穿透，避免控制器已恢复而界面仍显示旧的等待状态时，完整窗口被留在不可点击状态。工作台首次收边仍使用原生几何过渡；进入侧边后固定原生窗口为完整展开尺寸，展开/收起只改变圆角可见区域，不再逐帧移动或缩放 HWND，也不重新布局输入框和按钮。新露出的背景与控件同步重绘；不进入输入事件循环，也不切换可见性。工作态主动添加分层样式后显式设置不透明度 255。活动指示持续更新已有线条。截图开始不强制结束动画，捕获隐藏期间更新可见区域也不会重新显示窗口。

`Ctrl+Alt+Enter` 展开补充，`Ctrl+Alt+Space` 暂停/继续，`Ctrl+Alt+Esc` 停止。独立线程通过不可见的消息窗口异步接收 Windows Raw Input，仅记录有设备标识的鼠标移动。没有全局低层鼠标钩子，也不抑制系统鼠标消息：即使 Python 忙碌，系统指针与其他应用也无需等待观察线程。Agent 的 `SendInput` / `SetCursorPos` 不会触发设备移动回执，避免经过浮窗时误展开；不提供设备标识的输入环境仍可用展开快捷键。系统快捷键在同一独立线程注册；暂停或停止快捷键注册失败时阻止真实任务启动。

侧边伸展按实际经过时间插值，约 320ms；右侧和顶部固定。中途反向或恢复工作时，从当前可见区域继续，不从完整原生尺寸重新开始。Windows 窗口区域同时裁剪绘制和鼠标命中，隐藏部分不会遮挡下面的应用；悬停判断也使用可见区域。标题、图标和活动线条复用已有 Canvas 项目。关闭本窗口的 DWM 系统过渡，设置仅作用于本应用窗口，不修改系统动画偏好。

常规工作台保留歌词式状态转场、有限状态历史和折叠记录，不虚构完成百分比。公共文案过滤明显的凭据格式，不展示模型 thought 或原始 Python 日志。这不等同于完整敏感信息检测。

## 对话与执行入口

每条新请求先进入 `Assistant`。普通对话通过 UFO 当前支持的 completion 接口复用 `APP_AGENT` 的服务与模型配置，但使用 Mirally 自己的对话协议；不需要单独配置 `CONVERSATION_AGENT`，也不会启动桌面执行器、截图、窗口枚举或输入操作。确认进入桌面工作后，才由运行时适配器启动 UFO 原生 Session。

模型结合当前会话区分直接回复与桌面工作：问候、解释、讨论、建议和文字创作在主窗口回答；实际操作应用、文件、浏览器或查看屏幕才交给桌面执行器。含糊请求可先澄清。比如「怎么打开记事本」回答方法，「帮我打开记事本」进入执行。生产环境使用语义判断，不以关键词表决定；离线演示只提供明确标注的有限示例。

问答保持窗口位置和大小，主区域呈现用户消息与助手回复，保留换行、代码缩进与可复制文字。普通对话隐藏桌面暂停/接管控件，生成期间提供停止按钮和可继续输入的编辑框。模型等待期间收到新补充，会使旧回复或旧执行决定失效，再结合补充回答。协议格式错误只做一次纠正，不降级为桌面执行；纠正保留原问题，不把格式提示当成新问题。

当前一轮仍是串行处理：桌面工作进行中的新输入作为该工作的补充，尚未提供独立的并发旁路聊天。文本回复在模型完整返回后展示，尚未实现逐 token 流式显示。路由依赖模型能力，有限验证不保证所有表达均判断正确。

## 运行中补充与桌面控制

用户无需手动停止或暂停任务才能写补充。鼠标进入展开面板的输入区、悬停最小化按钮、使用输入快捷键或打开完整工作台时，控制器登记输入意图，使旧观察版本失效；仅靠近展开不登记。模型请求可以继续等待；鼠标、键盘和截图操作由原子门禁协调：

1. 尚无桌面操作进行时，立即让出输入与焦点。
2. 如果点击、输入或截图已经开始，等当前操作结束后再启用编辑。
3. 输入期间禁止发出新的桌面操作。窗口保持可编辑，任务保留进度。
4. 发送/收起后，GUI 先恢复外部焦点与输入穿透，再释放执行器。
5. 返回的新控制版本使旧计划失效；执行器重新观察，加入已排队的信息后再决策。

这是同一 Windows 桌面上的控制权协调，不承诺用户与 Agent 同时向不同窗口发送键盘输入。发送不能回滚已执行的操作。

补充与追问回复携带独立回执 ID。界面接收时显示「已收到 · 下一步将调整」；手动暂停时显示继续后交给 Agent。执行器实际加入 `user_answers` 后才显示「已加入当前任务上下文」。结束前未消费的输入标记为未加入上下文。显示预览最多 800 字符，执行器仍接收完整输入。演示回执明确标记模拟接收。

新补充会使待确认操作失效，已排队的旧批准也不能越过版本检查。确认后的敏感操作仍需重新观察并验证目标；历史会话中的批准不会授权新任务。

GUI 心跳与窗口操作确认超时会阻止后续桌面动作。停止优先于编辑、回复和确认，关闭窗口先结束工作线程。已发出的外部调用不能强制回滚，结束状态等待其返回。

## 会话记忆

`ConversationStore` 将会话保存在 `config/openassist/conversations/`，Git 忽略。默认恢复最近会话；可在侧栏或「历史」中恢复和新建，在「记忆」中检查和清空当前上下文。新建保留旧会话文件；清空当前会话会删除其中的消息、结果、补充和更早摘要，保留会话 ID，不删除其他会话或独立的运行日志。

保存用户消息、助手回复、已加入上下文的补充、工作终态与结果；单条结果最多 12000 字符，产物路径可随结果保存。对话和工作共用连续上下文，兼容原有会话文件。没有保存截图、控件坐标、模型隐含推理或敏感操作批准。新执行器通过 `conversation_context` 获取历史，并被明确要求重新验证桌面和文件状态、优先遵循新要求。

原「已保留 N 轮交流」是已结束交流的实时计数，不是会话上限。现改为「当前会话 · 现有 N 项交流记录」，并在「记忆」页明确说明本地保留与模型参考的不同范围。执行器的「最近 6 条」指桌面操作步骤，不是只能进行 6 轮聊天。历史长度限制用于控制请求体积、延迟和成本；并不意味着所有本地记录都能在每次回答中被完整参考。

边界如下：

- 当前任务仍保留完整用户答案与补充，执行历史带最近 6 条。
- 每个会话最多保留 40 项任务的有限记录，更早项目变为最多约 5000 字符的摘录。
- 每轮选择最近最多 8 项已结束任务，历史内容预算约 14000 字符；单项文本及补充条数也有限制。界面记录不等同于每次全部发送给模型。
- 摘录和裁剪为确定性处理，尚未增加模型摘要、语义检索或个人偏好的自动提取。
- 重启时未结束的任务标记为中断；恢复会话不代表自动继续操作电脑。
- 存储失败时保留窗口内会话并提示；损坏文件不会被默默覆盖。
- 长期个人偏好、跨会话知识库和用户主动保存的长期事实仍是下一阶段。

本地会话记录可包含用户任务内容；常见凭据模式会被遮盖，但不承诺识别所有秘密。清空会话不会删除 UFO 调试日志。

## 截图与控件隔离

优先设置并查询 `WDA_EXCLUDEFROMCAPTURE`，等待桌面合成刷新后允许观察。已用当前机器的 UFO `PhotographerFacade` 实际捕获路径验证：完整工作台、紧凑卡片、展开卡片及输入状态均能保持可见、不透明，同时截图呈现其背后的测试应用。2026-10-03 亮屏后再次完成原生排除与隐藏回退的像素对比，输入穿透、窗口尺寸和不透明度恢复检查均通过。

原生能力不可用时回退为截图期间隐藏。隐藏前关闭本窗口的 DWM 过渡，避免渐隐残影；核实不可见并刷新桌面合成后才截图，随后无激活恢复。不改变系统全局动画设置。

捕获排除只影响像素，不能消除 UIA 节点。因此 `WindowsComputer.observe` 同时排除自身进程的窗口，使浮窗不会进入窗口/控件映射。截图握手与桌面操作门禁始终保留。

## 验证与限制

### 本机体验复查

在项目根目录运行 `.\run.ps1 --demo` 可检查布局与交互；它不调用模型、不操作电脑，演示会话不用于验证重启后的持久化。检查实际保存与模型行为时使用 `.\run.ps1`。

1. 小窗口点击顶部「历史」，创建两个会话并分别发送消息，再点击条目切换；当前项应高亮，选中后返回对应对话，不能出现会话下拉框。
2. 最大化窗口，直接点击左侧会话条目切换；还原窗口后仍能通过「历史」找到同一会话。长列表可滚动，也可用方向键和 Enter 选择。
3. 空闲时点击「浮窗」。鼠标靠近后检查展开，再移出空输入区等待收回；右侧应固定，隐藏区域不应挡住其他应用。
4. 执行期间查看展开浮窗，活动指示应继续变化。移入输入区补充并发送，检查「已收到」到「已加入当前任务上下文」的回执；未发送草稿在收起和展开后仍应保留。
5. 遇到追问或确认时在主窗口回复；恢复执行后应自动回到浮窗。主窗口不应残留为无法点击的状态。
6. 在普通问答完成后关闭并重新启动正式入口，检查当前会话恢复；新建另一会话后，不能默认引用前一个会话的上下文。历史会话恢复不代表继续执行上次未完成的桌面动作。

这些步骤区分可复现的行为与视觉体验。自动化检查可证明本次采样中的几何位置、布局与输入隔离正确，不能单独证明所有环境下的动画都无颤动。
