# 桌面体验实现与验证

Mirally 当前默认采用「晴空蓝」：银白背景、深灰文字、少量天蓝强调。正式图标选定 [01 · 合翼 A](design-concepts/mirally/a-monogram/README.md)，原始 [天蓝界面探索](design-concepts/2026-10-03/sky-blue/README.md) 保留作为设计记录。明亮天蓝用于状态指示，按钮与小字号强调使用更深的蓝以保证可读性；原有主题仍可选。现有 Python 3.10、根目录 `.venv`、`run.ps1` 和模型配置均沿用，Python 包和配置目录保持 `openassist`。

## 品牌、开屏与自适应布局

窗口标题、任务栏图标、主界面与浮窗使用同一合翼 A 标记和 Mirally 名称。`branding.py` 从应用自身的 `assets/` 加载透明 PNG 和多尺寸 ICO，不依赖工作目录或设计输出目录；晴空蓝与石墨主题均使用透明背景素材。

开屏在主窗口内部展示图标和字标，约 0.94 秒后向上收起。首个点击或按键可以跳过，首个输入字符仍保留；启用「减少动态效果」时直接进入主界面。计时使用实际经过时间与 Tk 回调，不阻塞输入、不建立额外弹窗，关闭时清理回调。

工作区宽度达到 980 逻辑像素时增加会话侧栏，展示当前会话、会话选择、新建入口、最近六条交流与工作状态；主区域随剩余空间伸展，对话字号、内边距和输入区同步适配。窄窗口保持单列，在标题栏下直接提供会话选择和「＋ 新建」，无需进入记忆面板。运行时禁用会话切换和新建，避免混用上下文。小窗口追问/确认时收起重复的介绍文案，为补充回执和确认按钮保留空间。歌词式工作状态采用有上限的居中内容列，避免全屏时文字仍挤在小窗口大小的区域内。空闲或任务结束后隐藏桌面暂停/接管控件，为对话和小窗口输入留出空间。

设置、记忆、记录按钮使用独立的选中状态：浅色填充、蓝色文字和完整圆角边框。按钮资源以四倍分辨率抗锯齿生成，边框为 1.25 逻辑像素，焦点环为 1.75 逻辑像素，并预留间隔；选中、悬停、按下与键盘焦点可以组合。卡片内按钮使用匹配表面背景的样式，避免圆角外出现矩形底片，各状态不改变按钮尺寸。

## 工作台与侧边形态

- `run.ps1`：对话助手与单 Agent 桌面执行器。
- `run.ps1 --demo`：离线演示，不调用模型、不操作桌面，会话默认仅存在内存中。
- `run.ps1 --legacy`：原界面与 UFO 原生多智能体适配器；没有本轮连续会话、浮窗输入门禁的完整保证。

启动时显示可滚动的对话。空闲时即可点击「收回」手动进入浮窗；进入桌面执行流程时自动用约 320ms 过渡收至当前显示器工作区右侧。等待回答/确认或正在停止时，不允许手动收回问题窗口。紧凑卡片约 272×120 逻辑像素，展示动作、步骤和状态；物理鼠标靠近后展开约 370×340 的补充面板。仅展开查看进度不会取得输入控制权，工作与活动指示继续。进入输入区或按展开输入快捷键时才请求输入控制。展开和收起保持同一侧边锚点，窗口始终不透明。减少动态效果设置会跳过过渡与活动节奏。

展开面板提供输入、最近回执、暂停、停止和打开会话。发送后收回；离开空输入面板后自动收回；未发送草稿会保留，已发送文本不再被迁移回草稿。追问与敏感确认打开完整工作台以显示完整内容，回答或确认后随执行器恢复工作返回浮窗。由浮窗临时打开的追问保留返回状态，即使关闭自动收边也能正确返回。手动收边仍不能绕过待回答的问题。最大化、全屏和最小尺寸在收边前保存，重新打开完整工作台时恢复。主题共用排版、字体与交互路径。

从浮窗提交新请求后，理解意图期间仍保持浮窗。若随后决定执行桌面任务，直接在浮窗进入工作，不先展开主窗口；若返回普通聊天回复，则在完成后打开工作台呈现完整回答。不能根据暂时的 `conversation` 模式提前判断最终是聊天还是执行。

恢复工作通过 `resume_working()` 完成形态交接，再启用工作态的输入穿透，避免控制器已恢复而界面仍显示旧的等待状态时，完整窗口被留在不可点击状态。几何过渡按实际经过时间插值，按约 16ms 调度。每帧由 `WindowSession.resize_surface()` 统一完成：一次禁止立即重绘的原生尺寸变更、不单独重绘的圆角更新、Tk 内部布局同步，然后绘制完整的窗口与子控件。重绘不先擦除父窗口，避免尺寸、圆角和子控件分别更新时暴露空白帧；不进入输入事件循环，也不切换可见性。工作态主动添加分层样式后，显式设置 255 的不透明度，避免依赖 Tk 对已有 alpha 值的处理。活动指示独立更新已有线条。截图开始不强制结束动画，捕获隐藏期间的几何更新也不会重新显示窗口。

`Ctrl+Alt+Enter` 展开补充，`Ctrl+Alt+Space` 暂停/继续，`Ctrl+Alt+Esc` 停止。独立线程通过不可见的消息窗口异步接收 Windows Raw Input，仅记录有设备标识的鼠标移动。没有全局低层鼠标钩子，也不抑制系统鼠标消息：即使 Python 忙碌，系统指针与其他应用也无需等待观察线程。Agent 的 `SendInput` / `SetCursorPos` 不会触发设备移动回执，避免经过浮窗时误展开；不提供设备标识的输入环境仍可用展开快捷键。系统快捷键在同一独立线程注册；暂停或停止快捷键注册失败时阻止真实任务启动。

侧边形态的伸展以原生 `GetWindowRect` 为起点，每帧用「固定右坐标 − 当前宽度」计算左坐标，避免分别插值产生边缘漂移。关闭本窗口的 DWM 系统过渡，避免系统再次变换自定义动画的中间尺寸。标题、图标和活动线条复用已有 Canvas 项目，不再在每次宽度变化时删除重建。设置仅作用于本应用窗口，不修改系统动画偏好。

常规工作台保留歌词式状态转场、有限状态历史和折叠记录，不虚构完成百分比。公共文案过滤明显的凭据格式，不展示模型 thought 或原始 Python 日志。这不等同于完整敏感信息检测。

## 对话与执行入口

每条新请求先进入 `Assistant`，复用 `APP_AGENT` 的现有模型与服务配置，用独立的 `CONVERSATION_AGENT` 调用类型避免套用桌面动作协议。此阶段没有桌面执行器、截图、窗口枚举或输入操作。

模型结合当前会话区分直接回复与桌面工作：问候、解释、讨论、建议和文字创作在主窗口回答；实际操作应用、文件、浏览器或查看屏幕才交给桌面执行器。含糊请求可先澄清。比如「怎么打开记事本」回答方法，「帮我打开记事本」进入执行。生产环境使用语义判断，不以关键词表决定；离线演示只提供明确标注的有限示例。

问答保持窗口位置和大小，主区域呈现用户消息与助手回复，保留换行、代码缩进与可复制文字。普通对话隐藏桌面暂停/接管控件，生成期间提供停止按钮和可继续输入的编辑框。模型等待期间收到新补充，会使旧回复或旧执行决定失效，再结合补充回答。协议格式错误只做一次纠正，不降级为桌面执行；纠正保留原问题，不把格式提示当成新问题。

当前一轮仍是串行处理：桌面工作进行中的新输入作为该工作的补充，尚未提供独立的并发旁路聊天。文本回复在模型完整返回后展示，尚未实现逐 token 流式显示。路由依赖模型能力，有限验证不保证所有表达均判断正确。

## 运行中补充与桌面控制

用户无需手动停止或暂停任务才能写补充。鼠标进入展开面板的输入区、使用输入快捷键或打开完整工作台时，控制器登记输入意图，使旧观察版本失效；仅靠近展开不登记。模型请求可以继续等待；鼠标、键盘和截图操作由原子门禁协调：

1. 尚无桌面操作进行时，立即让出输入与焦点。
2. 如果点击、输入或截图已经开始，等当前操作结束后再启用编辑。
3. 输入期间禁止发出新的桌面操作。窗口保持可编辑，任务保留进度。
4. 发送/收起后，GUI 先恢复外部焦点与输入穿透，再释放执行器。
5. 返回的新控制版本使旧计划失效；执行器重新观察，加入已排队的信息后再决策。

这是同一 Windows 桌面上的控制权协调，不承诺用户与 Agent 同时向不同窗口发送键盘输入。发送不能回滚已执行的操作。

补充与追问回复携带独立回执 ID。界面接收时显示「已收到 · 下一步将调整」；手动暂停时显示继续后交给 Agent。执行器实际加入 `user_answers` 后才显示「已加入当前任务上下文」。结束前未消费的输入标记为未加入上下文。显示预览最多 800 字符，执行器仍接收完整输入。演示回执明确标记模拟接收。

新补充会使待确认操作失效，已排队的旧批准也不能越过版本检查。确认后的敏感操作仍需重新观察并验证目标；历史会话中的批准不会授权新任务。

GUI 心跳与窗口操作确认超时会阻止后续桌面动作。停止优先于编辑、回复和确认，关闭窗口先结束工作线程。已发出的外部调用不能强制回滚，结束状态等待其返回。

## 会话记忆

`ConversationStore` 将会话保存在 `config/openassist/conversations/`，Git 忽略。默认恢复最近会话；可在「记忆」中查看、新建、恢复和清空。新建保留旧会话文件；清空只删除当前会话的摘要内容，不删除其他会话或独立的运行日志。

保存用户消息、助手回复、已加入上下文的补充、工作终态与结果；单条结果最多 12000 字符，产物路径可随结果保存。对话和工作共用连续上下文，兼容原有会话文件。没有保存截图、控件坐标、模型隐含推理或敏感操作批准。新执行器通过 `conversation_context` 获取历史，并被明确要求重新验证桌面和文件状态、优先遵循新要求。

边界如下：

- 当前任务仍保留完整用户答案与补充，执行历史带最近 6 条。
- 每个会话最多保留 40 项任务的有限记录，更早项目变为最多约 5000 字符的摘录。
- 每轮选择最近最多 8 项已结束任务，历史内容预算约 14000 字符；单项文本及补充条数也有限制。界面记录不等同于每次全部发送给模型。
- 摘录和裁剪为确定性处理，尚未增加模型摘要、语义检索或个人偏好的自动提取。
- 重启时未结束的任务标记为中断；恢复会话不代表自动继续操作电脑。
- 存储失败时保留窗口内会话并提示；损坏文件不会被默默覆盖。
- 长期个人偏好、跨会话知识库和用户主动保存的长期事实仍是下一阶段。

本地会话记录可包含用户任务内容；常见凭据模式会被遮盖，但不承诺识别所有秘密。清空会话不会删除 UFO 调试日志。

## 截图与控件隔离

优先设置并查询 `WDA_EXCLUDEFROMCAPTURE`，等待桌面合成刷新后允许观察。已用当前机器的 UFO `PhotographerFacade` 实际捕获路径验证：完整工作台、紧凑卡片、展开卡片及输入状态均能保持可见、不透明，同时截图呈现其背后的测试应用。2026-10-03 亮屏后再次完成原生排除与隐藏回退的像素对比，输入穿透、窗口尺寸和不透明度恢复检查均通过。

原生能力不可用时回退为截图期间隐藏。隐藏前关闭本窗口的 DWM 过渡，避免渐隐残影；核实不可见并刷新桌面合成后才截图，随后无激活恢复。不改变系统全局动画设置。

捕获排除只影响像素，不能消除 UIA 节点。因此 `WindowsComputer.observe` 同时排除自身进程的窗口，使浮窗不会进入窗口/控件映射。截图握手与桌面操作门禁始终保留。

## 验证与限制

- 产品单元测试覆盖会话持久化/恢复/清空/损坏/限长、补充回执、模型等待期间编辑、桌面动作互斥、重复回复、确认失效及停止优先。
- `tests/test_edge_companion.py` 覆盖等待状态下恢复工作、临时打开后的返回、最大化/全屏恢复、草稿发送与拒绝恢复、原生几何更新等回归；`tests/test_startup.py` 覆盖开屏生命周期、跳过、取消与回调清理。
- `tests/test_pointer_monitor.py` 验证 Raw Input 设备移动解析、失效消息处理、不抑制普通鼠标输入，以及真实 Windows 消息窗口的快捷键传递和退出清理；禁止注册全局同步鼠标钩子，并检查后台线程异常。
- 内核测试检查真实提示构造包含前任务结果与本次补充、旧计划失效、最后操作边界校验、UIA 自身排除，以及原有填写、循环检测等回归。
- `tools/preview_interface.py` 检查完整界面的主题、追问、确认、回执和小窗口布局。
- `tools/preview_edge_interface.py` 创建真实 Tk 浮窗，检查靠近展开、运行中发送、草稿保留、按钮文字、确认、会话恢复及新会话隔离。
- `tests/test_assistant.py` 检查问答不创建桌面执行器、不要求输入隔离、保留对话角色、补充与停止使旧决定失效，以及格式异常不触发桌面工作。
- `tools/preview_conversation.py` 验证真实主窗口中的问候、连续问答、可见回答、固定几何位置、小窗口布局和新会话清空。
- `tools/preview_mirally.py` 验证品牌、开屏首键保留、减少动态效果、按钮状态、最大化/全屏往返、小窗口确认、输入穿透切换，以及动画过程中捕获排除标志与隐藏回退。使用 `tools/ui_preview_capture.py` 直接渲染本进程窗口，在可用时支持熄屏预览；空白或全黑结果报错，不作为成功截图保存。
- `tools/preview_companion_navigation.py` 验证空闲收回、窄窗口直接新建/恢复会话、宽窄导航切换、等待意图判断及执行期间不跳回主窗口，以及普通回复完成后的可读性。
- `tools/preview_mirally_motion.py --working` 在合成背景上录制实际桌面中的浮窗，启用真实工作态的分层和鼠标穿透样式，检查可见轮廓逐步展开、收起，以及展开状态下的活动变化。同时检查始终位于窗口内部的固定区域，防止只凭外框尺寸通过却漏掉内部空白闪帧。录制使用独立线程，等待 DWM 合成并包含分层窗口。输出 GIF、逐帧对照图和测量记录；采样不能覆盖显示器呈现的每一帧，不作为无闪烁的绝对保证。
- `tools/preview_button_states.py` 展示不同 DPI 和主题下的按钮组合状态，`--surface` 检查卡片表面的圆角边缘。
- `tools/verify_assistant_live.py` 使用已配置的真实模型检查问候、知识问答、连续追问、操作方法与操作请求；只测试对话和路由，不实际执行桌面动作。
- `tools/verify_desktop_isolation.py` 用合成测试应用进行实际截图像素对比，覆盖三种窗口形态、原生排除、隐藏回退、样式与不透明度。

2026-10-03 最新验证：产品层 64 项单元测试通过，包含意图尚未确定时保持浮窗和逐帧右边缘锁定回归；`preview_companion_navigation.py`、`preview_edge_interface.py`、`preview_mirally.py` 与 `verify_desktop_isolation.py` 通过。最小窗口还检查补充回执末字的实际绘制边界，避免新增导航挤掉回执。界面预览见 [本轮界面预览](../output/mirally-preview/index.html)。约 320ms 的展开记录到 20 次几何更新，最大回调间隔 58.3ms；这是调度观测，不代表始终达到 60fps。

真实工作态录制取得 59 帧，展开和收起各观察到 9 种递进的可见尺寸；原生右边缘与录制画面中的可见右边缘漂移均为 0 像素，Canvas 项目没有重建。固定内部区域的最小画面覆盖率约为 99.7%，录制样本中未检测到整帧消失，展开期间工作指示持续变化。结果位于 `.artifacts/mirally-motion-working/verification.json`，录屏与逐帧对照图已更新到预览页。

此前熄屏期间采用直接窗口渲染检查布局，没有唤醒屏幕或更改电源设置。亮屏复查补齐了桌面截图像素隔离和可见动画检查。GUI 和桌面控制验证使用离线模型替身；真实模型的对话与路由测试不等于完整桌面任务验收。多显示器坐标使用 Windows 工作区与绝对坐标，但所有混合 DPI/全屏独占/捕获驱动组合尚未验证。原生多智能体、录音入口、长期偏好记忆仍不在本轮范围内。
