# Mirally 框架重构实施计划

状态：分支目标与验收计划已建立，2026-10-22；新框架尚未实现。

本分支 `codex/mirally-framework-refactor` 的目标是完整迁移至 Mirally 自有产品框架。以 [产品框架方案 v0.8](personal-agent-framework.md)、[扩展接口草案 v0.3](framework-extensions.md) 为起点，结合[调研证据](research/personal-agent-architecture-2026-10-22.md)验证和调整，不把阶段性原型当作最终交付。

## 2. 目标和约束

Mirally 拥有 Activity、Memory、Settings、Commitments、Initiative、Interaction、Context、Delivery 等产品职责及其状态。DSH 提供原生会话与模型运行基础，首选通过正式 Profile、Bundle/组合插件、Preset 与客户端扩展装配。Python 平台采集、记忆资产和 UFO 适配优先复用，不能假定搬动模块就能完成语义迁移。

每份持久状态有明确 owner 与唯一写入者；跨域读写通过接口。Context 只读组合，原生 transcript 保持单一权威；不额外自研模型循环、通用消息总线或第二套插件宿主。内置与外部能力使用同一组有类型的扩展契约，Skill、MCP 和插件按具体能力验收。

当前 DSH 固定源码是可行性研究依据，尚不是已安装并验收的产品依赖。先验证正式接缝；若缺少必要控制或界面入口，记录证据并调整集成方式，再展开迁移。产品目标、结构质量和恢复能力优先，允许有依据地调整或延后个别功能。

阶段可按垂直切片推进，但不能跳过前置控制与数据条件。每次完成应注明实际产出、测试方式、未覆盖边界和阶段状态；为实际行为更新运行说明、CHANGELOG 与产品记录。

### 阶段 1：先验证宿主接缝

使用临时配置和 fake 模型，不读取或改写现有产品私有状态。验证同一会话的输入去重、原生历史恢复、流式输出和 flush；取消后旧输出不能继续驱动动作。Python worker 的启动、就绪、停止、异常退出和清理均须有可观察结果。通过正式入口证明产品能装配和呈现后，再定目录和接口的稳定版本。

### 阶段 2：状态与控制先于后台能力

Interaction 拥有产品命令身份、会话代际及停止范围，runtime adapter 映射宿主事实；Activity、Memory、Settings、Commitments、Delivery 各自拥有领域状态。测试重启、重复命令、迟到回执、撤回来源、写入失败与旧 worker 存活。重启不得恢复已停止的动作；撤回须阻止后续使用，已进入模型的内容是否需要更换原生 Session 要明确。

现有保护状态、整理任务、回执和覆盖范围应有兼容或转换方案。记忆缺口与原始证据已清理需如实表达，不能将重新索引视为恢复了原始资料。物理共库或共进程不改变状态 owner。

### 阶段 3：用真实接入检验扩展契约

至少覆盖一个新来源、一个非 UFO 执行器和一个交互/投递入口，并检验跨领域插件组合。纯说明 Skill 与含脚本 Skill 分别验收；加载说明不自动开放 shell。MCP 工具、资源及模板、prompts 分别列兼容矩阵：固定研究版本的 DSH 缺少 prompts 支持，必须实现并验证明确适配或标注尚未支持。

名称冲突、接口版本不匹配、初始化失败、停用排空和资源撤销有明确结果。停用已加载 Skill 不等于清除了原生会话中的说明，插件也不能借接入绕过产品写入与行动边界。

### 阶段 4：完整体验与恢复

用生活回忆、偏好纠正、明确提醒、适时联系和实际行动共同验证框架，不让单一场景决定全部结构。固定提醒可不调用模型；Initiative 负责联系价值和时机，Delivery 根据持久记录与 Channel 回执处理发送、重试及未知结果。不能仅因执行工具返回成功就声明结果已完成，也不能宣称外部投递恰好一次。

UI 共用原生会话，能解释正在做什么、资料来源和停止结果。核对关窗、退出、重启、断连、模型不可用、关闭 Activity/后台模型/一般主动消息等状态。先用 fake 验证协议；真实桌面与 API 验收须在任务授权内另行进行，记录副作用、延迟与资源成本。

### 阶段 5：迁移演练后再替换默认入口

先在副本中验证配置、历史、记忆、证据与资产迁移，记录文件位置、schema 版本、数量与必要完整性检查；不擅自重写原私有配置。旧 OpenClaw 历史可先只读访问，不假定它与 DSH transcript 可无损互换。现有名称迁移脚本只负责改名与路径，不承担宿主或会话格式迁移。

新旧环境配置使用独立 home；消费同一实际资料前须确认旧采集和维护进程已停止，并验证共享来源/存储的跨环境排他与交接，再开放新写入者，确保只有一个 Activity 采集者和一个记忆维护者消费实际资料。回退需说明新系统期间产生的数据如何保留、导出或只读访问；不能只切回 Git 分支便宣称数据已恢复。完成故障和回退演练、替代体验验收后，再删除 OpenClaw 目标依赖与旧适配，并清理相应过时约束和文档。

## 4. 完成标准

最终默认入口运行自有 Mirally 产品框架与经过验证的 DSH 接入；安装可在其他 Windows 目录、空格/中文路径及不同工作目录复现。目标启动链不依赖 OpenClaw，UFO 子模块仍遵守只读约定。

关键领域有清晰接口、数据归属及恢复方法，Skill/MCP/插件支持范围有运行证据，生活和工作场景通过同一框架完成。阶段计划、骨架、fake 测试和文档不得代替真实实现；未交付或延后的能力应明确标注。具体性能与体验门槛在阶段 1 测量基线后确定，不预填未经验证的数字。
