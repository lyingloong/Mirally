# Mirally 框架重构实施计划

状态：2026-10-22 第一版已接通并切换默认入口，实际实现、安装与边界见 [框架第一版](framework-v1.md)。长期方向继续演进，真实外部模型/桌面效果和全新机器安装不在本轮离线验收中。

本分支 `codex/mirally-framework-refactor` 的目标是完整迁移至 Mirally 自有产品框架。用户已明确要求把 DSH 复制到仓库作为内核并直接修改；以[产品框架方案 v0.9](personal-agent-framework.md)、[扩展接口草案 v0.4](framework-extensions.md)为实施起点。原[调研证据](research/personal-agent-architecture-2026-10-22.md)保留历史上下文，不再要求先靠正式扩展证明所有接缝可用。

## 1. 已保存的基线

- 维护分支：`feat/mirally-openclaw-desktop`。
- 提交：`2eeb778a54dd3ab0e707ec014adda2d3078e556c`，已 push，切换前通过远端引用核对。
- 离线验证：Python `unittest discover -s tests -v` 共 877 项，2 项真实桌面测试跳过；Node 共 249 项，全部通过。Python 包含临时配置、隔离进程下的真实 UFO 导入及取消链路；这不等于真实桌面动作或模型效果验收。
- 保存内容包括包名与配置目录迁移、Activity/Memory 和现有 UI 改进，以及目标架构文档。未将私有配置、凭据、调试数据纳入提交，未修改 UFO gitlink 或内核。

新分支保存时仍运行 OpenClaw；后续同仓内核源码导入不表示已有经过构建和验收的新宿主、新产品数据库或启动链。保存 Git 分支不会备份本机配置、数据库和会话；它们必须按迁移阶段另行备份。

已知产品边界继续保留：默认关闭模型整理；原始证据清理受模型总结与完成回执保护，年龄和图片配额不会强行删除受保护资料；启用模型仅自动补最近一小时，更早积压尚无全历史补处理。新框架需明确处理这些状态，不能在更换宿主时丢弃它们。

## 2. 目标和约束

Mirally 拥有 Activity、Memory、Settings、Commitments、Initiative、Interaction、Context、Delivery 等产品职责及其状态。DSH 作为同仓源码内核提供会话与模型运行基础；允许直接修改其 API、loop、Session、持久化、宿主与客户端 UI。Profile、Bundle、Preset 和 Slots 等机制可按需复用，不强制每项内置改动都绕成插件。Python 平台采集和记忆资产优先复用；本阶段不接入 UFO，其实现仅作为未来 Windows 适配的参考，不能假定搬动模块就能完成语义迁移。

每份持久状态有明确 owner 与唯一写入者；跨域读写通过接口。Context 只读组合，内核 transcript 保持单一权威；在内核已有 loop 上修改，不在它之外另写第二套模型循环、通用消息总线或插件宿主。可扩展能力的内置与外部实现仍遵循同一组有类型的契约，普通内部代码无需全部公开。Skill、MCP 和插件按实际支持能力验收。

导入位置为 `kernel/dsh/`，固定 tag `dsh-v0.2.1-rc.2`、commit `687f282e8625c6b8d11ff58211a90524be2e4317`。纳入主仓库管理，不新增 DSH submodule；来源、许可证、工具链与本地修订见[内核说明](../kernel/README.md)和[上游记录](../kernel/dsh/UPSTREAM.md)。允许侵入式修改，不需要先证明官方接口无法满足；控制、存储与 UI 修改必须同步维护调用方、版本和回归测试。UFO 是另一个仍只读的 submodule，此授权不扩大到其内核。

构建依赖仍按内核锁文件和明确工具版本取得，源码、依赖目录与构建产物分开；不以修改 `node_modules/` 代替源码变更，也不静默使用全局或官方发行包启动。用户无需 clone 上游，但产品开发者需承担同仓内核的构建、测试、兼容和显式吸收上游责任。源码导入、依赖安装、成功构建、最小端到端、完整产品迁移是不同状态，分别记录。

阶段可按垂直切片推进，但不能跳过前置控制与数据条件。每次完成应注明实际产出、测试方式、未覆盖边界和阶段状态；为实际行为更新运行说明、CHANGELOG 与产品记录。

### 阶段 1：构建内核并跑通最小端到端

先核对 `kernel/dsh/` 的来源、完整性、许可证和锁文件，明确 Node/pnpm、原生组件与客户端构建步骤；记录实际成功命令、平台及本地内核修订。只导入文件、存在 package.json 或生成入口脚本不能标记本阶段完成。

在临时 home 中从同仓构建产物实际启动宿主与客户端，通过 fake 模型完成一次用户输入、流式回答、受控能力调用和结果投影；另验证输入去重、历史恢复、flush、取消后旧输出不再驱动动作。临时 Python worker 的启动、就绪、停止、异常退出和清理须可观察。无需调用真实模型或读取现有私有状态；缺口可直接修改内核 API/loop/Session/UI，不等待上游公开接缝。每个修改同时补最小回归，避免只绕过失败让界面看似能聊。

### 阶段 2：状态与控制先于后台能力

Interaction 拥有产品命令身份、会话代际及停止范围，Runtime 接口由同仓内核提供；Activity、Memory、Settings、Commitments、Delivery 各自拥有领域状态。可直接修改内核 admission、loop、Session 与实际 guard，让全部入口遵守同一控制契约。测试重启、重复命令、迟到回执、撤回来源、写入失败与旧 worker 存活。重启不得恢复已停止的动作；撤回须阻止后续使用，已进入模型的内容是否需要更换 Session 要明确。持久格式变化同步定义版本、旧数据读取或转换，不另写一份模型历史。

现有保护状态、整理任务、回执和覆盖范围应有兼容或转换方案。记忆缺口与原始证据已清理需如实表达，不能将重新索引视为恢复了原始资料。物理共库或共进程不改变状态 owner。

### 阶段 3：用真实接入检验扩展契约

至少覆盖一个新来源、一个非 UFO 执行器和一个交互/投递入口，并检验跨领域插件组合。纯说明 Skill 与含脚本 Skill 分别验收；加载说明不自动开放 shell。MCP 工具、资源及模板、prompts 分别列兼容矩阵：导入基线缺少 prompts 支持，可直接补内核 MCP 服务与调用面并测试；补齐前标注尚未支持，不能把源码可改等同已经兼容。

名称冲突、接口版本不匹配、初始化失败、停用排空和资源撤销有明确结果。停用已加载 Skill 不等于清除了原生会话中的说明，插件也不能借接入绕过产品写入与行动边界。

### 阶段 4：完整体验与恢复

用生活回忆、偏好纠正、明确提醒、适时联系和实际行动共同验证框架，不让单一场景决定全部结构。固定提醒可不调用模型；Initiative 负责联系价值和时机，Delivery 根据持久记录与 Channel 回执处理发送、重试及未知结果。不能仅因执行工具返回成功就声明结果已完成，也不能宣称外部投递恰好一次。

UI 可以直接修改内核客户端，共用同一会话权威，能解释正在做什么、资料来源和停止结果；不要求通过 Slots 包装全部界面变动。核对关窗、退出、重启、断连、模型不可用、关闭 Activity/后台模型/一般主动消息等状态。先用 fake 验证协议；真实桌面与 API 验收须在任务授权内另行进行，记录副作用、延迟与资源成本。

### 阶段 5：迁移演练后再替换默认入口

先在副本中验证配置、历史、记忆、证据与资产迁移，记录文件位置、schema 版本、数量与必要完整性检查；不擅自重写原私有配置。旧 OpenClaw 历史可先只读访问，不假定它与 DSH transcript 可无损互换。现有名称迁移脚本只负责改名与路径，不承担宿主或会话格式迁移。

新旧环境配置使用独立 home；消费同一实际资料前须确认旧采集和维护进程已停止，并验证共享来源/存储的跨环境排他与交接，再开放新写入者，确保只有一个 Activity 采集者和一个记忆维护者消费实际资料。回退需说明新系统期间产生的数据如何保留、导出或只读访问；不能只切回 Git 分支便宣称数据已恢复。完成故障和回退演练、替代体验验收后，再删除 OpenClaw 目标依赖与旧适配，并清理相应过时约束和文档。

## 4. 完成标准

最终默认入口运行自有 Mirally 产品框架与从 `kernel/dsh/` 构建、经过端到端验证的内核；安装可在其他 Windows 目录、空格/中文路径及不同工作目录复现，产物可追溯到上游基线、本地修订与依赖锁。目标启动链不依赖 OpenClaw 或全局 DSH，UFO 子模块仍遵守只读约定。

关键领域有清晰接口、数据归属及恢复方法，Skill/MCP/插件支持范围有运行证据，生活和工作场景通过同一框架完成。阶段计划、骨架、fake 测试和文档不得代替真实实现；未交付或延后的能力应明确标注。具体性能与体验门槛在阶段 1 测量基线后确定，不预填未经验证的数字。


## 第一版验收说明

实际运行由 `tools/verify_framework.py` 验证：构建后的原生 Agent loop、PiAI 模型适配、SQLite 产品状态、协议子进程和持久文件协作，回环模型与 MCP 只提供合成输入。覆盖命令去重、停止、冷重启、真实工具调用、偏好/提醒/入箱、可选主动候选、原生 Skill、实际脚本产物、MCP 全部接入面与可信插件生命周期。自有 UI 另经 Edge Headless 实测流式交互、cookie 刷新、会话切换、记忆纠正与搜索、提醒/已读、确认入口与窄屏布局。

迁移测试包含空格/中文路径、WAL、目标占用、来源变化、失败阶段清理、模型与偏好显式导入、旧历史索引和回退。它不代表已经迁移开发者私有数据或完成全新机器安装。UFO 内核与 gitlink 保持未修改，原有真实导入/初始化链继续回归；未执行真实桌面任务或外部付费 API。
