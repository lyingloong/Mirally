## 2. 本轮实现的采集诊断

`openassist/runtime/activity/service.py` 新增独立的 `collector_diagnostics` 状态，不修改原始 Observation。它保存有效通道开关、来源是否可用、输入与剪贴板通知所依赖的 worker 状态和原因，以及无正文的调用、事件、错误和丢弃计数。剪贴板通知与正文分开报告：metadata／structure 级别仍可启用通知，正文通道另需 content 级别授权。已启用来源不可用、输入 worker 退出或基础能力不足时，运行诊断保留 `degraded`，不因采集循环仍在运行而改写为健康。

诊断同时记录采集起止时间、最多 64 个暂停区间、调度队列合并／过期／丢弃计数，以及未能归属的输入、剪贴板信号、过期结果、黑帧等已知缺口计数。监控操作和外部 CLI 的暂停／恢复在实际被采集器应用时同步记录区间；只保留允许的原因代码，其他值标为 `unspecified`，不保存调用方正文。运行时每 10 秒保存一次采样健康；停止前捕获来源状态，停止后保留 `running_before_stop` 和原失败原因，并在内容 worker 结束后更新最终计数。

仅诊断写入失败时，关闭流程仍等待内容 worker、关闭视觉资源与存储，再向调用方报告原异常。若内容 worker 在有界等待后仍存活，则保留存储、worker 引用和最终视觉关闭步骤，报告未能安全关闭，供后续重试；不能提前释放这些资源并声称已经完成清理。停止后的诊断可通过本地 CLI `status` 读取，不需要重新启动采集器。

这些信息用于解释以后采集中某通道为什么没有数据。当前 80 条样本产生于修复前，原库只有 `stopped` 状态；无法从新增代码回填当时输入与剪贴板为零的原因。诊断是生命周期和来源健康采样，不是完整采集覆盖率或每次操作的真值记录。

快速焦点切换的输入归属仍采用保守策略：输入批次指向旧窗口，而采集器已观察到新窗口时，批次会被拒绝，避免借用新窗口身份或越过策略。这会漏掉部分已观察的输入计数。本轮保留这一限制并持久化拒绝计数；后续需要已知操作真值，验证有界窗口身份缓存、批次发生时间、控制主体和隐私策略后再修复归属。

## 3. 投影 v2 与事实时间线

本轮将确定性投影升级为 `activity.v2`。它把已观察动作、对象、内容变化、结果是否可确认、证据引用和未知分别表达。用户意图、阅读完成、保存、发送等没有对应证据的结论保持未知；未知基线输入快照表达为观察到控件文本，不表达为用户新输入。

证据保留原始 kind、来源 epoch、采集组、因果引用、采集时间、身份质量、窗口／显示器范围，以及来源实际保存的 UIA、OCR 和编辑信息。阅读摘要的截断单独标注，不能再把压缩摘要当作完整证据正文。由原始记录生成的事实表达也需要已知行为案例复核，不能仅因字段存在就称为真值。

组织与错误处理同步完善：

- 迟到 OCR 优先沿原截图引用恢复对象、范围和活动归属；无法确认因果来源时明确标记未知。
- 地址获取失败不会悄悄继承旧 URL；窗口资源上下文按来源 epoch 隔离，避免借用前次采集的页面。
- 显示器画面作为后台证据维护，不自动归属前台应用，也不因前台标题变化切断其连续性。
- 单条投影采用事务，失败结果进入可见、可重试的错误队列，避免留下半条活动或把处理错误伪装成成功。
- 停采集后执行最后一次有界追赶，处理已经落库但未投影的尾部记录；追赶错误需要明确报告。

本地事实时间线输出位置为：

- [timeline.md](../.artifacts/activity-fresh-review/timeline.md)：便于开发者阅读和复核。
- [timeline.json](../.artifacts/activity-fresh-review/timeline.json)：保留结构化动作、对象、变化、来源和未知。

这些文件可能包含用户采集内容，只留在被 Git 忽略的本地目录，不在本文引用正文。聚合审计、新投影对照库和回放结果也保存在 `.artifacts/activity-fresh-review/`。

## 5. 原始采集契约纠正与轨迹判断

按用户要求，获准采集的原始文字与结构不允许在采集阶段裁剪，截断仅用于后续摘要、筛选和查询输出。本批 13 次 UIA 的预算截断不符合这个要求；保留旧样本的 partial 标记，不能通过重建派生库恢复已经未保存的部分。

本次修正包括：

- UIA 完整遍历声明范围内的树，保存完整 Name、Value、Text 和控件属性，移除字符、节点、深度及响应字节裁剪；`capture_scope` 随原始记录、证据和事实时间线传递。密码、离屏及未知隐私状态子树仍按声明排除；这不代表应用未通过可访问性公开的内容也已采齐。
- OCR 保存完整正文与行／词结构；输入、剪贴板、窗口标题和合法地址栏值完整保存。剪贴板继续核对序号和 Unicode 完整性，旧截断输入基线不会被当作已知基线。
- Sensor 不再用小占位 payload 替换超限原文，Observation 不再因四个原始 JSON 字段超过 64 KiB 而拒绝入库。旧长度配置可加载，但不再裁剪原始内容；隐私开关和 worker deadline 仍生效。
- 读取失败、provider 错误或超时返回明确不可用诊断，不把成功读取的前缀标成完整正文。派生阅读摘要和查询仍可限制预算，完整原始记录及证据不随查询预算改变。
- 旧或自定义 OCR 来源报告缺失或截断时，首采和重试都保留原因与质量标记；不能因 `status=ok` 就把有损结果标成完整。
- 搜索索引和中文字面匹配读取完整 Evidence 正文，避免长输入或 OCR 只有前 12,000 字符能找到。Item 阅读摘要仍保持原预算；已有派生库可直接通过证据全文补充召回，无需为此改写原始库或重建索引。

离线回归覆盖超过 64 KiB 的中文和 emoji 正文、完整 OCR 行／词结构、超过旧节点／深度预算的树、完整剪贴板 Unicode、超长地址和保留首尾空白的标题。UIA 模式读取使用已安装 SDK 配合合成 element 验证：支持的通用模式不能因缺少控件便利方法而漏读，SDK 吞掉的 provider 错误不能被伪装为“不支持”。这些测试不采集用户桌面，也不证明所有应用 provider 都能公开完整正文。

上述修正对重新启动后的采集生效。本次没有启动用户桌面采集，也没有改写这批原始数据；截图仍沿用现有分辨率和资产保留策略。

## 6. 从逐条观察到窗口活动事件

产品目标是让开发者或模型可靠复盘用户在一段时间内的活动。动作、窗口状态和窗口文字是主要证据，截图、焦点控件、剪贴板与时间信息补充动作对象、上下文和前后变化。事件输出同时说明已观察到的事实、来源以及尚不能确认的结果。

新增 `ActivityOrganizer.activity_events()` 和独立 CLI `knowledge-events`，按已有 Episode 关联动作、窗口状态和文字证据。窗口切回、资源导航、采集缺口等仍遵循既有切段边界；迟到 OCR 回到原始截图所属活动，显示器画面独立列为后台证据。该视图直接使用已有 `activity.v2` 派生记录，不需要改写原始库，也不需要为查看旧样本再次重建实际目标知识库。具体字段、过滤与分页方式见 [Activity 事件视图](activity-events.md)。
