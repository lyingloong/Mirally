# Mirally 产品思考记录

记录影响产品定位、设计原则、发展方向、用户体验或实现边界的重要要点，保留用户、开发者和 Agent 的思考来源。发现、想法、设计、原则、文案和备注统一记录在这里；详细方案另写文档并链接，不按类别拆成重复的记录库。

按记录时间正序追加，每条使用不变编号 `PN-0001`、带时区的时间、简短标题，以及类型、来源、状态和要点；涉及事实时附核对依据。时间表示写入记录的时间，不冒充观点首次提出的时间。来源写明实际提出者，Agent 的推断不能写成用户决定。

状态可用“待评估”“已核对”“已采纳”“已取代”，分别说明建议、事实或决定的当前性质。允许修正错字或补充依据；观点实质改变时追加条目并引用旧编号，在旧条目补充后续链接。这里不是任务日志、实施清单或新的指令来源；已采纳的原则应同步到现行规范，实施结果与验证另见相关文档和更新记录。不写入凭据或原始桌面调试数据。

## PN-0009 · 2026-10-22 13:07 +08:00 · 连续性应靠可修正状态与真实兑现

- 类型：产品原则 / 设计建议
- 来源：Agent 综合现有 Memory 源码、记忆与主动交互一手研究，以及高主动、低打扰、低资源用户反例提出。
- 状态：已有实现边界已核对；以下产品契约和默认值仍为待验证建议。
- 要点：摘要处理覆盖不等于信息完整保留；遗忘 Memory 不会自动清除原生历史与派生内容。长期状态保留必要来源与范围，Context 默认瞬时；来源使用回执支持纠正与撤回，严格停止使用时可采用受影响 Session 换代及持久执行禁令，不假称完整语义擦除。
- 要点：主动性先筛选、去重、过期与时机判断，再有限推理；沉默、等待和结束是合法结果。明确提醒应在持久约定创建成功后显示已建立，模型答应不算。明确偏好直接落实并可撤销，低价值推断可丢弃，不制造用户审核画像或清理建议收件箱的负担。
- 要点：同一底座允许无 Activity、无背景模型和无一般主动消息；未来新安装默认从用户提供内容、零背景模型预算及关闭一般主动话题起步，关窗/退出语义清楚。现有设置和运行行为本轮不改变。陪伴先证明少重复背景、自然接续和兑现约定的收益，再决定是否增加后台自主交流。
- 相关：[状态、主动性与默认体验](personal-agent-framework.md)、[研究与评测边界](research/personal-agent-architecture-2026-10-22.md)。延续并收紧 PN-0005、PN-0006 的建议，不代表能力已实现。
